# 综合架构
**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">项目</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：一次性、有明确目标和交付物的工作（例：搭一套监控系统）</font>

**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">架构</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：系统的整体结构设计（例：楼的图纸，决定能扛多少压力）</font>

**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">运维常见架构</font>**

    - **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">单体架构</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：所有功能都在一个程序里（小公司初期）</font>
    - **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">微服务架构</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：把大系统拆成多个独立的小服务（大公司）</font>

**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">集群</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：多台服务器一起干同一件事（例：一群人分工干活，提高效率和可靠性）</font>

**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">运维常见集群</font>**

    - **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">Nginx 集群</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：多台 Nginx 一起处理网页请求</font>

**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">高可用</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：通过冗余避免单点故障，系统尽量不中断</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">双机热备：主节点干活，备节点待命，主挂了备自动接管</font>



## 1.用户访问网站流程
    1.用户通过浏览器输入oldboyedu.com->回车

    2.进行DNS解析->获取真实的公网IP地址

    3.用户通过tcp的三次握手发起连接->真实的公网IP

    4.连接会通过公网->路由器->交换机->抵达前端的防火墙

    5.防火墙根据自身访问规则，进行判定->如果恶意的连接则拒绝->如果是正常的连接则放行

    6.防火墙会将连接发送给负载均衡器->查看用户请求的内容->根据内容进行任务下发->下发给web服务器

    7.web服务接收请求后会根据请求进行判断

        如果是请求图片或者附件->存储服务

        如果请求的网站上的文章或者内容->缓存服务器->如果缓存服务器没有则->数据库

        数据库查询完数据之后会返回数据给web服务器->同时也会返回一份给缓存服务器

    8.数据库返回内容->web服务器->负载均衡->用户

#  网站业务五层架构（运维标准版）  
| 层级（从上到下，请求流向） | 核心职责 | 常用技术栈 | 运维核心工作 |
| --- | --- | --- | --- |
| **1. 接入层（负载均衡 / 反向代理层）** | 统一流量入口，请求分发，SSL 卸载，限流 | Nginx、LVS、HAProxy、Keepalived | 搭建高可用集群、配置负载均衡策略、SSL 证书管理 |
| **2. web 应用服务层** | 处理所有核心业务逻辑，是整个系统的大脑 | Tomcat、SpringBoot、Node.js、Go | 应用集群部署、扩容缩容、日志收集、JVM 调优 |
| **3. 存储服务层** | 存储非结构化数据（文件、图片、视频） | MinIO、FastDFS、OSS、NAS | 分布式存储集群、数据备份、容量监控 |
| **4. 数据缓存层** | 缓存热点数据，大幅降低数据库压力 | Redis、Memcached | 主从复制、集群搭建、持久化配置、内存优化 |
| **5. 数据持久化层** | 存储结构化核心业务数据 | MySQL、PostgreSQL、MongoDB | 主从复制、双机热备、分库分表、数据备份恢复 |


## <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">分层核心优势</font>
1. **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">职责单一</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：每一层只做一件事，便于问题定位和团队分工</font>
2. **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">独立扩展</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：哪层压力大就加哪层的服务器（比如图片多就扩容存储服务层）</font>
3. **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">故障隔离</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：缓存挂了不影响数据库，存储服务挂了不影响核心业务</font>
4. **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">技术选型灵活</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：不同层可以用最适合的技术栈</font>

## <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">一、单服务器架构（入门级，必掌握）</font>
**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">适用场景</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：个人博客、测试环境、小公司初期（日活 < 1000）、内部工具</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">核心特点</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：所有服务都跑在一台 Linux 服务器上，成本最低，运维最简单</font>

### <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">核心组件</font>
```plain
用户 → Nginx（静态+反向代理） → Tomcat/Node.js（业务） → MySQL（数据库）
```

1. <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">服务器系统初始化、安全加固（防火墙、SSH 配置）</font>
2. <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">一键部署 LNMP/LAMP 环境</font>
3. <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">配置 MySQL 每日自动备份</font>
4. <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">基础监控（CPU、内存、磁盘、进程）</font>
5. <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">日志切割和轮转</font>

### <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">优缺点</font>
<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">✅</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 优点：部署快、成本低、无分布式复杂度</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">❌</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 缺点：单点故障、性能上限低、无法扩容</font>

## <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">二、经典三层集群架构（运维标配，必精通）</font>
**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">适用场景</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：中小公司官网、电商店铺、内部管理系统（日活 1 万 - 10 万）</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">核心特点</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：三层分离，每一层都可以独立集群化，解决单服务器的性能和单点问题</font>

### <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">核心组件</font>
```plain
用户 → 接入层（Nginx双机热备） → 业务层（Tomcat集群） → 数据层（MySQL主从）
```

### <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">运维核心工作</font>
1. <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">部署 Nginx+Keepalived 双机热备，实现接入层高可用</font>

4. <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">配置统一日志收集（ELK）</font>
5. <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">全栈监控（Zabbix/Prometheus）</font>
6. <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">自动化发布脚本（Shell/Ansible）</font>

### <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">优缺点</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">✅</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 优点：数据库压力降低 90%、响应速度大幅提升</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">❌</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 缺点：增加了缓存的运维复杂度、数据一致性问题</font>

克隆前 虚拟机添加内网卡

![1547284385922-d4e105c4-071e-4d60-aef6-8a55404dedd0-image1.png](img/%E7%AC%AC%E4%BA%8C%E9%98%B6%E6%AE%B5-%E7%BB%BC%E5%90%88%E6%9E%B6%E6%9E%84%E5%9B%BE-02.png)

```bash
#新建网卡配置文件
nmcli connection add con-name eth1 ifname eth1 type ethernet \
ipv4.addresses 172.16.1.222/24 autoconnect yes ipv4.method manual 

#上面命令相当于手动创建了一个网卡配置文件
# cat /etc/sysconfig/network-scripts/ifcfg-eth1
connection add  连接增加
con-name       连接名字
ifname eth1     连接的是哪块网卡
type ethernet     类型以太网
ipv4.addresses    ip地址
autoconnect       是否开机自启动
ipv4.method	  manual   手动设置ipv4


```

## 克隆后的机器需要做如下操作
    1.修改主机名  hostnamectl set-hostname backup

    2.修改IP地址  sed -i 's#222#41#g' /etc/sysconfig/network-scripts/ifcfg-eth[01]

    3.重启服务器

    4.创建xshell标签->测试连接服务器是否成功

    5.基于已克隆好的机器快照
