# 一篇文章全面了解监控知识体系

> 监控是整个运维乃至产品生命周期中最重要的一环：事前及时预警发现故障，事后提供详实数据用于追查定位。本文梳理监控的目标、方法、工具、流程、指标分类与面试思路。

---

## 0. 监控目标

监控需要站在**公司业务角度**考虑，而不是针对某个监控技术的使用。

1. **对系统不间断实时监控**：这是监控最基本的含义。
2. **实时反馈系统当前状态**：正常 / 异常 / 故障，一眼可见。
3. **保证服务可靠性安全性**：监控的目的就是保障系统、服务、业务正常。
4. **保证业务持续稳定运行**：监控完善，故障第一时间告警、第一时间处理，业务连续性才有保障。

---

## 1. 监控方法

1. **了解监控对象**：比如 CPU 到底怎么工作？
2. **性能基准指标**：监控什么属性？如 CPU 使用率、负载、用户态/内核态、上下文切换。
3. **报警阈值定义**：多少算故障？CPU 负载多高算异常？
4. **故障处理流程**：收到报警怎么处理？有没有更高效流程？

---

## 2. 监控核心

1. **发现问题**：故障报警触发，收到告警信息。
2. **定位问题**：分析报警内容——一台服务器连不上，是网络问题、负载太高、还是触发了防火墙策略？
3. **解决问题**：按故障解决优先级处理。
4. **总结问题**：重大故障解决后归纳原因与防范，避免重复出现。

---

## 3. 监控工具

| 类别 | 代表 | 特点 |
| --- | --- | --- |
| 老牌 | MRTG / Ganglia / Cacti / Nagios / Smokeping | MRTG 流量图；Ganglia 分布式集群监控；Cacti 基于 PHP+SNMP+RRDtool 绘图；Nagios 侧重服务可用性告警；Smokeping 专攻网络延迟/丢包绘图 |
| 时序库 | OpenTSDB | 基于 HBase，秒级采集、永久存储，适合容量规划 |
| 王牌 | **Zabbix** | 分布式监控，支持 Agent/SNMP/IPMI/JMX 等采集，数据存 DB、触发告警，扩展性和二次开发能力强 |
| 国产 | 小米 Open-Falcon、TalkingData OWL | 面向互联网企业级监控 |
| 三方 | 监控宝、听云、云厂商自带监控 | 不赘述 |

> 本文基于 **Zabbix** 构建监控体系生态。

## 4. 监控流程（Zabbix）

1. **数据采集**：SNMP、Agent、ICMP、SSH、IPMI 等。
2. **数据存储**：默认存 MySQL，也可换其他数据库。
3. **数据分析**：故障复盘时提供图形与时间信息，定位故障所在。
4. **数据展示**：Web 界面（也可自研 APP/页面）。
5. **监控报警**：电话、邮件、微信、短信、报警升级机制等。
6. **报警处理**：按故障级别（重要紧急 / 重要不紧急）指派人员快速处理。

---

## 5. 监控指标

硬件监控 / 系统监控 / 应用监控 / 网络监控 / 流量分析 / 日志监控 / 安全监控 / API 监控 / 性能监控 / 业务监控。

### 5.1 硬件监控
- 早期靠机房巡检看灯光，费人力；现在用 **IPMI** 监控 CPU、内存、磁盘、温度、风扇、电压，并设阈值报警。
- IPMI 取不到的（如 Raid 队列状态）可用 **MegaCli** 探测；Zabbix 提供 `Zabbix IPMI Interface` 模板（默认能监控风扇/电源/部分温度）。

### 5.2 系统监控
- **CPU 重点**：上下文切换、运行队列、使用率。经验：每 CPU 运行队列 ≤3；用户态/内核态维持在 70/30；空闲 50%；上下文切换结合系统繁忙度综合看。
- 常用工具：`htop`、`top`、`vmstat`、`mpstat`、`dstat`、`glances`。
- 模板：`Zabbix Agent Interface`。
- **内存**：使用率、SWAP 使用率、内存溢出曲线。
- **IO**：磁盘使用率、吞吐量、写入繁忙度；网络看网卡流量。常用：`iostat`、`iotop`、`df`、`iftop`、`sar`、`glances`。
- 其他：进程端口、进程数、登录用户、Open File（见 Zabbix OS Linux 模板）。

### 5.3 应用监控
LVS、Haproxy、Docker、Nginx、PHP、Memcached、Redis、MySQL、RabbitMQ 等都要纳入。
- `nginx_status` / `PHP-FPM status` / `Redis info` 等自带状态页。
- 模板/接口：应用服务用 `Zabbix Agent UserParameter`；Java 用 `Zabbix JMX Interface`；MySQL 用 Percona 插件。

### 5.4 网络监控
多机房/全国用户场景需掌握各地到机房网络状态，用 **Smokeping**；也可借助监控宝、听云等三方工具监控 CDN。

### 5.5 流量分析
通过百度统计、Google Analytics、站长工具（嵌 JS）或开源 **Piwik** 分析订单来源、地区访问、交易额等。

### 5.6 日志监控
ELK Stack：`Logstash`（收集）+ `Elasticsearch`（存储+搜索）+ `Kibana`（展示）。部署更新异常可立即在 Kibana 看到；也可通过 Zabbix 过滤错误日志告警。

### 5.7 安全监控
四层 iptables、七层 Nginx+Lua 实现 WAF，日志归集 ELK 展示；或接入三方安全厂商（漏洞库覆盖服务/后门/数据库/配置/CGI/SMTP，更新 0day）。

### 5.8 API 监控
监控 REST API 的 GET/POST/PUT/DELETE/HEAD/OPTIONS 请求，**可用性、正确性、响应时间** 为三大核心指标。

### 5.9 性能监控
网页性能、DNS 响应、HTTP 建连时间、页面性能指数、响应时间、可用率等；Zabbix 用 `Zabbix Web 监控`。

### 5.10 业务监控
完善监控平台必须包含业务指标并设置阈值告警。电商示例：每分钟订单数、注册数、活跃用户、推广活动引入流量/用户/利润、出库/退货等，用 Screen 展示。

---

## 6. 监控报警

通知方式：短信、邮件最常用；也可电话、微信、报警升级。

## 7. 报警处理

- 通过**告警升级机制**自动处理（如 nginx down 自动拉起）。
- 严重业务故障按级别、业务指派运维处理；不同架构/服务方式不同，无固定模式。

---

## 8. 面试：如何回答监控相关问题

1. **硬件监控**：SNMP 监控路由交换、IPMI 监控服务器温度等；纯云环境可跳过。
2. **系统监控**：CPU 负载、上下文切换、内存、磁盘读写/使用率、inode；需配置触发器（默认太低会频繁误报）。
3. **服务监控**：LNMP 中 nginx/PHP 自带 status，MySQL 用 Percona 工具，Redis 用 info；要么服务自带，要么脚本实现采集+报警+图形。
4. **网络监控**：云主机非跨机房可不监控；跨机房推荐 Smokeping，或交给网络工程师。
5. **安全监控**：云安全组/硬件防火墙防 DDoS；系统层权限/密码/备份/恢复基础做好，Web 可用 Nginx+Lua/OpenResty 做 WAF。
6. **Web 监控**：Zabbix 自带 web 监控延迟/js/下载时间；或监控宝/听云（各地机房）。
7. **日志监控**：Nginx 50x/40x、PHP error 日志用 ELK 收集/存储/查询/展示。
8. **业务监控**：与开发/总监开会确认重要指标，脚本采集 + 触发器。
9. **流量分析**：百度/Google 统计嵌代码，或 piwik 自托管。
10. **可视化**：Screen + 第三方库美化，结合平台梳理系统间业务关系。
11. **自动化监控**：用 Zabbix 主动/被动模式，最好用 API 批量加主机/模板。

## 9. 监控总结

成熟开源监控难以完全满足需求，有条件公司自研（如小米 Open-Falcon）；也可基于 Sensu + InfluxDB + Grafana 定制。

## 常见面试题

1. **监控体系一般包含哪些环节？**
   采集 → 存储 → 分析 → 展示 → 报警 → 报警处理，形成闭环。

2. **Zabbix 相比 Nagios/Cacti 的优势？**
   分布式、采集方式多样（Agent/SNMP/IPMI/JMX）、数据入库可分析、触发器告警灵活、扩展与二次开发能力强。

3. **系统监控 CPU 重点看哪些指标？**
   使用率、负载（运行队列）、用户态/内核态比例、上下文切换次数。

4. **日志监控为什么常用 ELK？**
   Logstash 收集、Elasticsearch 存储+检索、Kibana 可视化，完整覆盖收集/存储/查询/展示四件事。

5. **业务监控为什么是监控体系的关键一环？**
   前面所有监控最终都是为业务连续性服务；无业务指标（订单/用户/利润）的监控是不完整的。

6. **如何避免监控误报/告警风暴？**
   合理设置触发器阈值、告警依赖、告警抑制、告警升级与聚合，避免低优先级频繁打扰。
