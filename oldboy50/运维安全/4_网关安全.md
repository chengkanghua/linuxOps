# 网关安全 - JumpServer 堡垒机教学

> 参考：JumpServer 官方文档（https://docs.jumpserver.org/，当前 V3 版，由杭州飞致云维护）。
> 本文档用于讲解 JumpServer 堡垒机的原理、部署与日常运维。具体命令与端口以官网最新文档为准。

---

## 一、为什么需要堡垒机

在没有集中管控的运维环境中，通常会面临以下问题：

- 服务器账号（root / 普通用户）分散在多人手中，难以追溯谁在何时做了什么；
- 运维人员直接 SSH / RDP 登录资产，出现误操作、越权操作时无法阻断与回溯；
- 等保合规（网络安全等级保护）要求对运维操作进行**事前授权、事中监察、事后审计**；
- 多云、多数据中心环境下，资产分散，缺乏统一的访问入口。

**堡垒机（运维审计系统）** 就是为了解决上述问题而生的"运维网关"。JumpServer 是广受欢迎的**开源堡垒机**，是符合 **4A 规范**（认证 Authentication、授权 Authorization、账号 Account、审计 Audit）的专业运维安全审计系统。

核心理念：**所有对资产的访问，都必须先经过 JumpServer 这一道"网关"**，由它统一完成身份认证、权限校验、会话录制与日志审计。

---

## 二、JumpServer 核心功能

JumpServer 的核心能力围绕 4A 展开，并覆盖完整的运维访问生命周期：

| 能力域 | 说明 |
| :--- | :--- |
| 用户管理 | 用户、用户组、角色、组织（多租户）的集中管理 |
| 资产管理 | 资产、资产树（节点）、账号（特权用户 / 系统用户）的统一纳管 |
| 账号管理 | 账号收集、账号改密、账号备份（企业版 X-Pack） |
| 权限管理 | 授权规则：将"用户 / 用户组"与"资产 / 节点 / 账号"绑定 |
| 远程应用 | Web 终端、数据库 Web GUI、Windows 远程应用（Remote App） |
| 会话审计 | 实时监控、命令记录、录像回放、文件传输审计 |
| 日志审计 | 登录日志、操作日志、改密日志等 |
| 文件管理 | 基于 Web 的 SFTP 文件上传 / 下载 |
| 作业中心 | 批量命令执行、定时任务（基于 Ansible 自动化） |
| 系统设置 | 基本设置、邮件 / 通知、认证设置、存储设置 |

### 可纳管的资产类型

JumpServer 不仅能管 Linux，还支持广泛的 IT 资产：

- **SSH 类**：Linux / Unix / 网络设备等（通过字符协议连接）；
- **Windows**：原生 RDP 连接、Web 方式连接；
- **数据库**：MySQL / MariaDB / Oracle / SQL Server / PostgreSQL / ClickHouse 等；
- **NoSQL**：Redis / MongoDB 等；
- **GPT**：ChatGPT 等；
- **云服务**：Kubernetes / VMware vSphere 等；
- **Web 站点**：各类系统的 Web 管理后台；
- **应用**：通过 Remote App 连接各类应用。

### 产品特色

- **开源**：零门槛，线上快速获取和安装；
- **分布式**：轻松支持大规模并发访问；
- **无插件**：仅需浏览器，提供极致的 Web Terminal 使用体验；
- **多云支持**：一套系统，同时管理不同云上的资产；
- **云端存储**：审计录像云端存储，永不丢失；
- **多租户**：一套系统，多个子公司 / 部门同时使用；
- **多应用支持**：数据库、Windows 远程应用、Kubernetes 等。

## 三、系统架构与核心组件

JumpServer 采用**分层架构**，自上而下分为五个层级：

1. **负载层**：对外提供统一入口，可做负载均衡 / 反向代理（如 Nginx）；
2. **接入层**：接收用户连接请求，按协议分发给对应的协议组件（Koko / Lion / Chen 等）；
3. **核心层**：Core 组件，负责认证、授权、调度、API 等核心逻辑；
4. **数据层**：MariaDB / MySQL（业务数据）、Redis（缓存 / 消息）等；
5. **存储层**：录像、文件等审计数据的存储（本地或对象存储）。

> 注意：实际部署时各组件以容器 / 微服务方式运行，五层是逻辑分层而非必须的物理分离。

### 核心组件说明

| 组件 | 作用 |
| :--- | :--- |
| **Core** | JumpServer 的核心组件，其他所有组件都依赖它启动，负责 API、认证、授权、调度 |
| **Koko** | 服务于**类 Unix 资产**，通过 SSH、Telnet 协议提供字符型连接（Web 终端、SFTP） |
| **Lion** | 服务于 **Windows 资产**，用于 Web 端访问 Windows 资产（RDP） |
| **Chen** | 服务于**数据库**，用于通过 Web GUI 方式访问数据库资产 |
| **Magnus** | 服务于**数据库**，用于通过客户端代理方式访问数据库资产 |
| **Razor** | 服务于 RDP 协议，JumpServer Client **默认**使用 Razor 访问 Windows 资产 |
| **XRDP** | 服务于 RDP 协议，主要通过 JumpServer Client 方式访问 Windows 2000 / XP 等旧系统 |
| **Kael** | 服务于 GPT 资产平台，用于纳管 ChatGPT 等资产 |
| **Celery** | 处理异步任务，执行自动化 / 作业中心相关任务 |
| **Video** | 将 Razor / Lion 组件产生的会话录像转换为 MP4 格式 |
| **Panda** | 基于国产操作系统的应用发布机，用于调度 VirtualApp 应用 |

> 企业版（X-Pack）还提供工单、云同步、账号改密、账号收集、账号备份、资产登录复核、连接方式控制、短信设置、角色列表、组织管理、界面设置、认证设置等扩展能力。

## 四、部署安装

### 4.1 环境要求

- **JumpServer 服务器**：主流 Linux 发行版（基于 Debian / RedHat，包括国产操作系统），建议 ≥ 4 核 8G 内存；
- **被纳管资产**：
  - Linux 主机：需开启 SSH（22），且能运行 Python（≥ 2.6）以支持自动化任务；
  - Windows 主机：需开启 RDP（3389），并视情况手动安装 **OpenSSH Server**；
  - 数据库：需授权 JumpServer 的 **Core 与 Koko** 组件远程访问权限（如 MySQL 3306）。

### 4.2 安装方式

官方推荐生产环境使用**离线安装包**部署。常见部署形态包括：

- **Linux 单机部署（推荐起步）**：一键脚本 / 离线包，适合中小规模；
- **Linux 集群模式部署**：多节点分担负载，适合大规模并发；
- **Kubernetes Helm 模式部署**：容器化编排；
- **Docker Compose**：社区版常用的本地 / 测试部署方式。

#### 社区版在线一键安装（参考）

```bash
# 在干净的 Linux 服务器上执行（需 root 或 sudo）
cd /opt
# 下载并运行官方一键安装脚本（具体版本 / 地址以官网"资源下载"页为准）
curl -sSL https://github.com/jumpserver/jumpserver/releases/latest/download/quick_start.sh -o quick_start.sh
bash quick_start.sh
```

安装完成后，浏览器访问 `http://<JumpServer服务器IP>:<服务运行端口>`，默认用户名 `admin`，密码 `admin`，**首次登录后务必修改默认密码**。

> 说明：JumpServer 通过 `jmsctl.sh`（管理脚本）进行日常管理，例如：
> ```bash
> ./jmsctl.sh status     # 查看组件状态
> ./jmsctl.sh restart    # 重启所有组件
> ./jmsctl.sh upgrade    # 升级版本
> ```
> 各组件默认端口（Web、SSH 接入、RDP 接入、数据库代理、Redis 等）请查阅官网"安装部署 → 网络端口说明"，生产环境建议仅对必要端口放通访问控制。

## 五、核心概念

在正式使用 JumpServer 前，先理解几个贯穿始终的核心概念：

- **用户 / 用户组**：使用 JumpServer 登录并访问资产的人；可分组批量授权；
- **资产 / 节点（资产树）**：被纳管的服务器、数据库等；资产以树形结构（节点）组织，便于分类与批量授权；
- **账号**：
  - **特权用户（privileged user）**：JumpServer 用于连接资产、做连通性测试与推拉账号的"管理员"账号，通常仅支持 SSH 协议；
  - **系统用户 / 普通账号**：用户实际登录资产时使用的账号；
- **授权规则**：JumpServer 的权限核心，把 **谁（用户 / 用户组）** 能访问 **什么（资产 / 节点）** 的 **哪个账号（账号 / 系统用户）** 绑定起来；
- **组织（多租户）**：一套系统下可划分多个组织，实现数据隔离，适合集团 / 多部门共用。

记住一句话：**用户通过授权规则获得对资产的访问权，资产上的操作全部经由 JumpServer 代理并被录制审计。**

## 六、快速上手（初始化流程）

按以下标准路径完成投产前的基础初始化：

### 6.1 规划与安装

1. 准备一台 Linux 服务器，按前述方式安装 JumpServer；
2. 浏览器访问控制台，使用 `admin / admin` 登录并修改密码。

### 6.2 编辑资产树

- 进入 `资产管理 → 资产列表`；
- 在根节点 `Default` 上右键，新建子节点（如 `SSH Server`、`RDP Server`、`DB` 等），构建资产树。

### 6.3 创建资产与账号

- 在对应节点下点击 `创建` 主机资产，填写 IP、操作系统等；
- 同步创建**特权用户**（用于连接性测试等自动化任务，填管理员账号密码）；
- 数据库类资产：在 `数据库` 分类下选择 MySQL 等，填写地址、节点并添加登录账号。

### 6.4 创建授权规则

- 进入 `权限管理 → 资产授权 → 创建`；
- 将 **用户 / 用户组** 与 **资产 / 节点** 及 **账号** 绑定（注意一对多 / 一对一关系，不同系统资产应分别授权）。

### 6.5 用户登录验证

- 普通用户登录后，点击右上角 `Web 终端`；
- 只能看到**被授权**的资产，连接即可进入字符 / 图形会话。

### 6.6 系统设置

- `系统设置 → 基本设置`：配置当前站点 URL、用户向导等；
- `系统设置 → 邮件设置`：对接 SMTP / EXCHANGE，用于通知与告警。

## 七、资产管理实战要点

### Linux 主机

- 确保目标机开启 SSH（22）；
- 创建资产时填写正确的 IP 与平台（Linux）；
- 配置特权用户（能用它成功 SSH 登录目标机）；
- 创建后可使用 JumpServer 的"测试连接"功能验证连通性。

### Windows 主机

- 开启 RDP（3389）；
- 如需执行自动化任务 / 批量命令，需先配置 Windows SSH（手动安装 OpenSSH Server）；
- Web 端访问走 Lion 组件，Client 方式（Razor）为默认。

### 数据库

- 通过 **Chen** 组件以 Web GUI 访问，或通过 **Magnus** 组件以客户端代理方式访问；
- 需提前在数据库中授权 JumpServer 的 Core 与 Koko 组件可远程连接。

## 八、权限与授权管理

授权规则是 JumpServer 权限控制的枢纽，三要素不可缺：

```
用户 / 用户组   ──┐
                  ├──>  授权规则  ──>  决定能否以某账号登录某资产
资产 / 节点     ──┤
                  │
账号 / 系统用户 ─┘
```

进阶权限控制手段：

- **命令过滤（危险命令拦截）**：可配置规则拦截 `rm -rf`、`reboot`、`mkfs` 等危险命令，事中阻断；
- **角色与细粒度权限**：通过角色控制用户在 JumpServer 控制台内的操作范围（企业版 / 组织管理能力更强）；
- **连接方式控制**：限制可使用 Web 终端、客户端、SFTP 等具体连接方式。

## 九、会话与审计（核心价值）

JumpServer 最大的价值在于**运维过程可审计、可追溯**。

- **Web 终端**：浏览器内直接打开字符 / 图形会话，无需本地安装客户端；
- **实时监控**：管理员可查看在线会话，必要时**打断、锁定**危险会话；
- **命令记录**：所有在会话中执行的命令都会被记录，可检索、可告警；
- **录像回放**：字符 / 图形会话全程录像（视频格式），事后可逐帧回放，定位问题；
- **文件传输审计**：基于 SFTP 的文件上传 / 下载操作同样被记录；
- **日志审计**：登录日志、操作日志、改密日志等多维度留存，满足合规审查。

> 审计录像支持云端 / 对象存储，避免本地磁盘写满导致审计数据丢失。

## 十、安全加固建议

堡垒机本身也是高价值目标，应同步加固：

1. **立即修改默认口令** `admin / admin`，并为所有账号设置强密码 / 双因子认证；
2. **限制访问来源**：JumpServer 控制台与接入端口仅对运维网段开放，禁止公网裸奔；
3. **配置命令过滤规则**：对危险命令做拦截，降低误操作与恶意破坏风险；
4. **定期审计日志与录像**：形成巡检习惯，及时发现异常登录与操作；
5. **及时升级版本**：关注官方安全通知（如 JS-xxxx.x.xx 漏洞公告），及时打补丁；
6. **最小化授权**：遵循最小权限原则，按岗按需授权，避免"一人通配全部资产"。
