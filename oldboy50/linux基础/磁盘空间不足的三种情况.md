# 磁盘空间不足的三种情况

> 创建文件时提示 **`No space left on device`**，通常有**三种**原因。本文逐一模拟、排查并给出解决办法，最后讲解 Linux 删除文件的底层原理。

## 一、inode 被用完

### 模拟环境
```bash
[root@LornBlood ~]# dd if=/dev/zero of=/dev/test count=10 bs=10M
10+0 records in
10+0 records out
104857600 bytes (105 MB) copied, 0.303514 s, 345 MB/s

[root@LornBlood ~]# mkfs.ext4 /dev/test
mke2fs 1.41.12 (17-May-2010)
/dev/test is not a block special device.
Proceed anyway? (y,n) y
...
25688 inodes, 102400 blocks
...
[root@LornBlood ~]# mount -o loop /dev/test /app/logs/
[root@LornBlood ~]# df -Th
Filesystem     Type     Size  Used Avail Use% Mounted on
/dev/sda3      ext4      19G  1.7G   17G  10% /
/dev/test      ext4      93M  1.6M   87M   2% /app/logs

[root@LornBlood logs]# touch test_{1..100000}.txt
[root@LornBlood logs]# mkdir haha.txt
mkdir: cannot create directory `haha.txt': No space left on device
```

### 排查思路
```bash
# 1. 第一时间 df -Th 看磁盘使用率
[root@LornBlood logs]# df -Th
/dev/test      ext4      93M  2.4M   86M   3% /app/logs
# 使用率才 3%，说明不是 block 用完（df 看的是 block 信息）

# 2. 用 df -i 看 inode 使用率
[root@LornBlood logs]# df -i
Filesystem      Inodes IUsed   IFree IUse% Mounted on
/dev/test        25688 25688       0  100% /app/logs
# inode 已 100% —— 小文件太多导致
```

### 解决：找出小文件最多的目录并清理
```bash
# 文件名存放在上级目录的 block 里，目录越大说明里面文件越多
[root@LornBlood logs]# find / -type d -size +800k | xargs ls -hdl
drwxr-xr-x 3 root root 884K Jul 29 14:34 /app/logs

# 记录好该目录的权限，把目录删除再创建回来
```

> **要点**：`df -h` 看 block，`df -i` 看 inode。小文件过多会耗尽 inode 而 block 还有剩余。

## 二、Block 被占满

```bash
# 模拟：生成一个大文件（时间较长）
[root@LornBlood logs]# seq 100000000000 >> test.txt

[root@LornBlood logs]# df -Th
/dev/test      ext4      93M   91M     0 100% /app/logs
[root@LornBlood logs]# mkdir test.dir
mkdir: cannot create directory `test.dir': No space left on device
```

### 排查：逐级 du -sh 找最大的文件
```bash
[root@LornBlood logs]# du -sh /* | sort -h
[root@LornBlood logs]# du -sh /app/* | sort -h
90M	/app/logs
[root@LornBlood logs]# du -sh /app/log/* | sort -h
90M	/app/logs/test.txt

# 确认作用后删除（或剪切到其他分区）
[root@LornBlood logs]# rm -rf /app/logs/test.txt
```

> **要点**：用 `du -sh` 逐级定位大文件，确认其作用后再删；不能删就剪切到别的分区。

## 三、inode 和 block 都有空间，但仍提示空间不足

**原因**：那个大文件**正在被进程占用**（已删除但句柄未释放）。

```bash
[root@LornBlood logs]# df -Th
/dev/sda3      ext4      19G  5.8G   12G  33% /

# 按排查 block 的方式找出大文件，例如 /var/log/messages
[root@LornBlood logs]# rm -rf /var/log/messages
[root@LornBlood logs]# df -Th
/dev/sda3      ext4      19G  5.8G   12G  33% /
# 删除后磁盘使用大小没变化！
```

### 排查：lsof 查看被删除但仍被占用的文件
```bash
[root@LornBlood logs]# lsof | grep delete
bash       2259 root  cwd       DIR  8,3          0     130925 /root (deleted)
rsyslogd  22037 root    1w      REG  8,3 4444445244     130895 /var/log/messages (deleted)
```

### 解决：重启占用该文件的服务
```bash
[root@LornBlood logs]# /etc/init.d/rsyslog restart
Shutting down system logger:                               [  OK  ]
Starting system logger:                                    [  OK  ]

[root@LornBlood logs]# df -Th
/dev/sda3      ext4      19G  1.7G   17G  10% /
# 空间已释放
```

> **为什么选择重启服务而不是直接 kill 进程？**
> 因为该文件一直被程序调用，说明服务依赖它。重启服务会**重新生成**该文件，服务继续正常工作；而直接结束进程不会有这个效果。

## 四、Linux 下删除文件的原理

**删除文件/目录，首先看当前用户对该文件的父目录有没有权限**——因为目录名和文件名存放在上级目录的 block 里，删除操作实际是在操作父目录的 block。

### 文件存储原理（4 点）
1. Linux 通过 **inode**（索引节点号）区分文件，而**不是**文件名
2. 存储分两部分：**inode**（存放文件属性） + **block**（存放实际数据）
3. **文件名存放在父目录的 block 里**
4. inode 与文件名的**对应关系**也存放在父目录的 block 里

### 查找文件的过程
- **按绝对路径**查找：按路径名一级一级在 block 里查找"文件名 ↔ inode"的对应关系
- **按相对路径**查找：在当前目录的 block 里查找对应关系

找到 inode 号后，通过 inode 确定属性，判断能否操作，修改后把新属性保存回 inode 块。

### 删除过程三步
1. **判断权限**：先看上级目录是否有权限；有权限则通过文件名找到 inode 信息
2. **删除文件名**：此时**只删除了文件名**，inode 和 block 并未删除；等到有新数据写入该 block，数据才真正丢失
3. **真正的删除条件**：`i_count` 和 `i_link` 都为 0

### 通俗类比（帮助理解"删了为啥空间没释放"）
> 一个人（**Block 块**）具有身份证（**inode 号**）和姓名（**文件名**），他正在工厂上班（**相当于被进程调用**）。
> 我们删除文件，就是删除了"这个人的姓名"和"他的身份证信息"的对应关系，但这个人（block）和身份证（inode）还是存在的。只有等 Linux 垃圾回收，或有新数据写入该 block，原始数据才真正消失。
>
> **为什么文件被删除后进程还能继续使用？**
> 因为一个人在工厂上班时，别人不会去查你的个人信息——不管你有没有身份，你都能一直干活。**重启服务**相当于工厂下班再上班，上班时就要查个人信息了，信息不存在就没法上班了。
