## 第1题 安装linux系统对硬盘分区时，必须有哪两个分区？

```bash
第一句（最重要）
CentOS 6 最少需要 2 个分区：/（根分区）和 swap（交换分区）。

第二句
CentOS 7 最少只需要 1 个分区：/（根分区），swap 可选。

第三句（神级加分回答）
生产环境标准分区： /boot + / + swap + /data
针对你刚才的疑问，补充 1 句救命答案
问：CentOS 6 只分一个 / 能装吗？会卡死吗？
答：能装，有警告但能继续，不会卡死，只是没交换分区，内存不够时会变慢。

生产标准分区（永远不会错）
/boot    1G
/        200G
swap     8G（内存>8G）
/data    剩余所有空间

为什么生产环境一定要单独分 /boot？（面试必背）
3 个核心原因：
防止根分区写满，导致系统无法启动
如果 /boot 放在根分区 / 里
根分区满了 → 系统内核无法更新、无法启动
单独分 /boot → 绝对不会被占满
便于系统修复、救援模式使用
符合企业标准化规范

所有服务器统一分区：/boot + / + swap + /data  
#物理内存大于等于64G 时候 swap不分配
```

## 第2题 简述RAID0,RAID1,RAID5，三种工作模式的工作原理及特点。

```bash
RAID 0 又称条带化（Striping），它将数据分割成大小相等的数据块，并行地写入到多个磁盘中
例如，有两块磁盘组成的 RAID 0，数据会交替地存储在这两块磁盘上，磁盘 1 存储数据块 1、3、5 等，磁盘 2 存储数据块 2、4、6 等。当读取数据时，多个磁盘同时工作，并行读取各自存储的数据块，再组合成完整的数据。
优点：读写性能极高。
缺点：数据可靠性差
适用数据不重要服务器，数据库从库

RAID 1 即镜像（Mirroring），数据会完整地同时写入到多个磁盘中。2的倍数盘都可以
优点：数据安全性高。
缺点：存储成本高。因为数据完全冗余，实际可用存储空间仅为所有磁盘总容量的一半。
100冗余   适用数据库重要  数据库 监控服务器

RAID 5 采用条带化存储，并在每个条带中加入校验信息。假设由三块磁盘组成 RAID 5，数据以条带形式分布在三块磁盘上，同时生成校验数据，校验数据也分布在这三块磁盘上。 至少3块盘，可以坏一块盘。
优点：兼顾了数据安全性和存储成本。
缺点：写入性能相对 RAID 0 会有一定下降，因为每次写入都需要计算和更新校验数据。
一般企业都可以
```

## 第4题 一个ext3的文件分区，当使用touch test.file命令创建一个新文件时报错，报错的信息是提示磁盘已满，但是采用df -h命令查看磁盘大小时，只使用了60%的磁盘空间，为什么会出现这个情况？说说你的理由，如何解决？

df –h 查看的是block使用情况，

使用df –i 查看inode 使用情况  有大量小文件

解决： 查找出大量的小文件 确认后删除  find / -type d –size +1M

> **补充说明**：这是典型的 **inode 耗尽**问题。
>
> - `df -h` 看的是 **block**（存储空间），`df -i` 看的是 **inode**（文件数量）。
> - 每个文件至少占用一个 inode，即使文件是空的。大量小文件会把 inode 用完，此时 block 还有剩余，但已无法创建新文件。

> find / -xdev -type d -size +1M         # 找出小文件堆积的目录

> find /dir -type f -print | head

## 第29题 什么是cache？什么是buffer，二者的区别是什么？在什么情况下需要使用它们？

cache 缓存区    读             高并发高负载

buffer 缓冲区	写

> **补充说明**：
>
> | 对比 | buffer（缓冲区） | cache（缓存区） |
> | --- | --- | --- |
> | 面向 | **写**（把分散的写操作攒起来） | **读**（把读过的数据留一份） |
> | 目的 | 缓解"快设备→慢设备"速度差，减少磁盘碎片写 | 加速重复读取，避免每次都读磁盘 |
> | 例子 | 写数据时先放内存，攒够一批再落盘 | 再次读同一文件直接从内存返回 |
> | 命令体现 | `free -h` 的 `buffers` | `free -h` 的 `cached` |
>
> **什么时候需要**：
> - 高并发写（日志、数据库刷盘）依赖 buffer 合并写入，减少 IO 次数。
> - 热点数据反复读取依赖 cache（如 Web 静态资源、数据库索引）。
>
> **记忆口诀**：**写 buffer，读 cache**。
> ```bash
> free -h                    # 看 buffers / cached
> sync                       # 强制把 buffer 中的数据落盘
> echo 3 > /proc/sys/vm/drop_caches    # 释放 cache（测试用，生产慎用）
> ```
> **注意**：`free` 里 `used` 高不代表内存不够，因为 buffer/cache 可被回收；要看 `available`。

## 第58题 写一个脚本将数据库备份并打包到远程服务器192.168.1.1/backup目录下。

**答**：

```bash
#!/bin/bash
# 功能：备份 MySQL 数据库，打包后传到远程服务器 192.168.1.1:/backup
BACKUP=/backup
DATE=$(date +%F)
REMOTE=root@192.168.1.1

# 1. 导出数据库（建议用 ~/.my.cnf 免密，不要明文写密码）
mysqldump -uroot -p'yourpass' --all-databases --single-transaction > $BACKUP/db-$DATE.sql

# 2. 打包压缩
tar zcf $BACKUP/db-$DATE.tar.gz $BACKUP/db-$DATE.sql

# 3. 传到远程（需提前配置 ssh 免密）
scp $BACKUP/db-$DATE.tar.gz $REMOTE:/backup/

# 4. 清理本地 7 天前的备份
find $BACKUP -name "db-*.tar.gz" -mtime +7 -delete
```

**生产建议**：
- 密码不要写在脚本里，用 `~/.my.cnf` 配置 `[client] user/password`，或直接 `mysqldump` 免密。
- InnoDB 加 `--single-transaction` 保证一致性，不锁表。
- 配合 `crontab` 定时执行：`00 02 * * * /bin/sh /server/scripts/db_bak.sh >/dev/null 2>&1`
- 更大量数据用 `rsync` 增量同步，比 `scp` 更高效。

## 第84题 进程有哪三种状态？

就绪状态   运行状态    阻塞状态

> **补充说明**：**就绪（Ready）、运行（Running）、阻塞（Blocked）**
>
> | 状态 | 含义 |
> | --- | --- |
> | **就绪** | 进程已具备运行条件，等待 CPU 分配时间片 |
> | **运行** | 正在占用 CPU 执行 |
> | **阻塞** | 因等待某事件（IO、信号、锁）暂时停止，即使给 CPU 也不能运行 |

>
> **注意**：题目问的是操作系统原理的三态模型；实际 `top` 看到的是更细的状态划分。

## 第90题 请适用linux系统命令统计出establish状态的连接数有多少

**答**：

```bash

ss -ant | grep -i established | wc -l
# 说明：ss -ant 中 ESTAB 是 ESTABLISHED 的缩写，grep -i 忽略大小写

# 方法三：用 awk 精确匹配状态列（避免匹配到其他内容）
ss -ant | awk '$1=="ESTAB"{n++}END{print n+0}'
netstat -ant | awk '$6=="ESTABLISHED"{n++}END{print n+0}'

> | --- | --- | --- | --- |

## 第103题 简述tcp3次握手的过程。

**答**：

TCP 是面向连接的协议，建立连接需要**三次握手**（Three-way Handshake）：

| 步骤 | 方向 | 发送的标志位 | 状态变化 |
| --- | --- | --- | --- |
| 第一次 | 客户端 → 服务端 | `SYN=1, seq=x` | 客户端进入 `SYN_SENT` |
| 第二次 | 服务端 → 客户端 | `SYN=1, ACK=1, seq=y, ack=x+1` | 服务端进入 `SYN_RECV` |
| 第三次 | 客户端 → 服务端 | `ACK=1, ack=y+1` | 双方进入 `ESTABLISHED` |

**通俗理解**：
1. 客户端："我要连你，我的序号是 x"（SYN）
2. 服务端："收到，我同意连，我的序号是 y，确认你的 x"（SYN+ACK）
3. 客户端："收到你的 y，连接建立"（ACK）

**为什么是三次而不是两次？**
两次握手只能保证"客户端能发出去"，无法确认"服务端也能正常发回来"。三次握手让**双方都确认自己和对方的收发能力正常**，同时避免已失效的连接请求突然到达服务端、白白占用资源。

> 抓包验证：`tcpdump -n -i eth0 port 80` 可以看到 SYN → SYN,ACK → ACK 三个包。

## 第117题 一台主机有多块网卡，当该主机向外发出一个数据包时，在哪个环节决定的使用哪块网卡发出该数据包？

**答**：

由**路由表（路由选择环节）**决定从哪块网卡发出。

**数据包发出时的决策过程**：
1. 应用程序产生数据，交给 TCP/UDP（传输层），再交给 IP 层（网络层）。
2. **IP 层根据目标 IP 查本机的路由表**（`ip route` / `route -n`）。
3. 按"最长前缀匹配"原则选中最匹配的一条路由。
4. 该路由指定了出口设备（dev，即网卡）和下一跳（网关）。
5. 数据包交给对应的网卡，再由网卡通过 ARP 解析下一跳的 MAC 地址后发出。

```bash
ip route                     # 查看路由表（看每条路由的 dev 是哪块网卡）
ip route get 8.8.8.8         # 查"访问某个目标地址时会走哪条路由/哪块网卡"（最直接）
route -n                     # 传统写法
```

> **要点**：网卡本身不决定路由，**路由表决定出口网卡**。如果有多条默认路由，靠 `metric`（优先级）选；`ip route get <目标IP>` 是判断"实际会走哪块网卡"最快的命令。

## 第118题 IP地址为121.136.157.191/255.255.192.0，该地址所在的网络的网络号是多少？该地址所在网段的广播地址是多少？该网段的广播域一共有多少个ip地址？

**答**：

已知 IP `121.136.157.191`，掩码 `255.255.192.0`（即 `/18`，因为 255.255.192.0 = 前 18 位为 1）。

**计算过程**：
- 掩码第三个字节是 `192` = 二进制 `11000000`，所以**块大小 = 256 - 192 = 64**。
- IP 第三个字节是 `157`，落在哪个块？`157 ÷ 64 = 2 余 29` → 属于第 2 块（从 0 开始），块起始 = `2 × 64 = 128`。
- 所以网络号的第三个字节是 `128`，主机位（第四字节及第三字节后 6 位）全置 0。

| 项目 | 值 |
| --- | --- |
| **网络号（网络地址）** | `121.136.128.0` |
| **广播地址** | `121.136.191.255` |
| **可用地址范围** | `121.136.128.1` ~ `121.136.191.254` |
| **可用主机数量** | 16382 个 |

**推导可用数量**：主机位 = 32 - 18 = 14 位 → 总地址数 `2^14 = 16384`，减去网络号和广播地址 → `16384 - 2 = 16382`。

**广播地址怎么算**：下一个网络号是 `128 + 64 = 192`（即 `121.136.192.0`），广播地址 = 下一个网络号减 1 = `121.136.191.255`。

## 第131题 解释top命令和vmstat命令。

**答**：

### top：实时查看系统整体与进程资源占用
```bash
top                     # 默认 3 秒刷新一次
top -d 1                # 1 秒刷新
top -p PID              # 只看某个进程
top -Hp PID             # 查看某进程内的线程（Java 高 CPU 排障常用）
```
**交互快捷键**：`P` 按 CPU 排序、`M` 按内存排序、`1` 展开显示每个 CPU 核心、`q` 退出。

**头部关键行**：
- `load average`：1/5/15 分钟平均负载
- `%Cpu(s)`：`us` 用户态、`sy` 内核态、`id` 空闲、`wa` **等待 IO**（`wa` 高说明磁盘瓶颈）、`st` 被虚拟机偷走
- `Mem` / `Swap`：内存与交换分区使用情况

### vmstat：查看系统的进程、内存、swap、IO、CPU 整体统计
```bash
vmstat 1 5              # 每 1 秒采样 1 次，共 5 次
```
**关键列含义**：

| 列 | 含义 |
| --- | --- |
| `r` | 运行队列长度（**长期大于 CPU 核数说明 CPU 不够用**） |
| `b` | 不可中断睡眠的进程数（通常是等 IO） |
| `si` / `so` | 从 swap 换入 / 换出（**不为 0 说明内存不足**） |
| `bi` / `bo` | 块设备读 / 写（磁盘 IO 量） |
| `us` / `sy` / `wa` | CPU 用户态 / 内核态 / 等待 IO 百分比 |

> **区别**：`top` 侧重"看哪个进程占资源"（找元凶），`vmstat` 侧重"看系统整体瓶颈在哪"（判断 CPU/内存/IO 哪块有问题）。排障时通常先用 `vmstat` 定性，再用 `top` 定位具体进程。

## 第134题 简述对tcp/ip的认识，tcp是第几层的，ip是第几层的。

**答**：

TCP/IP 模型（四层）与 OSI 七层模型的对应关系：

| TCP/IP 四层 | 对应 OSI | 主要协议 | 本题答案 |
| --- | --- | --- | --- |
| 应用层 | 应用层/表示层/会话层 | HTTP、HTTPS、FTP、DNS、SSH、SMTP | —— |
| **传输层** | 传输层（第 4 层） | **TCP**、UDP | **TCP 在第 4 层（传输层）** |
| **网际层（网络层）** | 网络层（第 3 层） | **IP**、ICMP、ARP、路由协议 | **IP 在第 3 层（网络层）** |
| 网络接口层 | 数据链路层/物理层 | 以太网、MAC、网卡驱动 | —— |

**对 TCP/IP 的认识**：
- **TCP（Transmission Control Protocol）**：面向连接、可靠传输，提供重传、排序、流量控制、拥塞控制，用于 HTTP、SSH、MySQL 等要求"不能丢包"的场景。
- **IP（Internet Protocol）**：无连接、尽最大努力交付，负责**寻址和路由**，把数据包从源主机送到目标主机；它不保证可靠，可靠性由上层的 TCP 兜底。
- 两者分工：**IP 负责"送到哪、怎么走"（寻址路由），TCP 负责"送得可靠、不乱序"（可靠传输）**。

> 记忆口诀：**TCP 管可靠（传输层），IP 管找路（网络层）**；TCP 封装在 IP 报文里，IP 又封装在以太网帧里，逐层封装与解封装。

## 第136题 简单描述tcp/ip建立连接,断开连接的过程。

**答**：

### 建立连接：三次握手
1. 客户端发 `SYN`（seq=x）→ 服务端，客户端进入 `SYN_SENT`
2. 服务端回 `SYN + ACK`（seq=y, ack=x+1）→ 客户端，服务端进入 `SYN_RECV`
3. 客户端回 `ACK`（ack=y+1）→ 服务端，双方进入 `ESTABLISHED`，可以传数据

### 断开连接：四次挥手
TCP 是全双工的，收发两个方向要**分别关闭**，所以需要四次：

| 步骤 | 方向 | 内容 |
| --- | --- | --- |
| ① | 主动方 → 被动方 | `FIN`，表示"我这边没数据要发了" |
| ② | 被动方 → 主动方 | `ACK`，确认收到 FIN（此时被动方可能还有数据要发） |
| ③ | 被动方 → 主动方 | 被动方数据发完后，发 `FIN` |
| ④ | 主动方 → 被动方 | `ACK`，确认，等待 `2MSL` 后关闭 |

**为什么断开要四次、建立只要三次？**
因为建立连接时，服务端的 `SYN` 和 `ACK` 可以**合并**在一个包里发出；而断开时，被动方收到 FIN 后可能还有数据没发完，**不能立刻发 FIN**，只能先回 ACK，等数据发完再发 FIN，所以 ACK 和 FIN 分成了两次。

**相关状态**：主动方经历 `FIN_WAIT1` → `FIN_WAIT2` → `TIME_WAIT`；被动方经历 `CLOSE_WAIT` → `LAST_ACK`。

> 排障提示：服务端出现**大量 `CLOSE_WAIT`** 通常是程序 BUG（收到关闭请求但没调用 close），需要排查应用代码。

```bash

**更推荐的做法**：如果是要看"谁访问本网站最多"，**直接分析 Nginx/Apache 访问日志**比抓包高效得多：

# 访问量 Top 10 的 IP（首选方案）
awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -10
```

**两者区别**：

| 方式 | 适用场景 |
| --- | --- |
| `tcpdump` 抓包 | 排查网络层问题（连接建立失败、丢包、异常流量），或没有访问日志时 |
| 分析 `access.log` | 统计访问量、Top IP、URL、状态码（**统计类需求首选**） |

> **原理**：`date +%N` 取纳秒（随机种子）→ `md5sum` 生成 32 位十六进制摘要 → `cut -c1-32` 取前 32 位。
>
> **更推荐的方式**：
> ```bash
> # 用系统随机源（更安全）
> tr -dc 'a-zA-Z0-9' < /dev/urandom | head -c32; echo
> openssl rand -base64 24
> mkpasswd -l 32 -s 0          # 需安装 expect
> ```
> **注意**：题目用的是 `date +%N`，严格来说只是"伪随机"，生产密码建议用 `/dev/urandom`。

## 第151题 一个文件的权限为rwsr-xr-x，其中s代表什么？

suid 权限  1755    代表所有用户运行这个文件相当于是root

> **更正**：`rwsr-xr-x` 中的 `s` 代表 **SUID 权限**，数字是 **4755**（**不是 1755**，1 是粘滞位 sticky）。
>
> **拆解**：
>
> | 位置 | 值 | 含义 |
> | --- | --- | --- |
> | 所有者 | `rws` | 原本 `rwx`，`x` 被 **s** 替代 → 设置了 **SUID**，数字 **4** |
> | 所属组 | `r-x` | **5** |
> | 其他人 | `r-x` | **5** |
>
> **所以完整数字权限是 4755**。
>
> **SUID 作用**：任何用户执行这个文件时，会**临时获得该文件所有者的权限**（这里所有者是 root，所以普通用户执行时相当于 root 身份）。
>
> ```bash
> chmod u+s file               # 加 SUID（数字写法 chmod 4755 file）
> ls -l /usr/bin/passwd        # 典型例子：-rwsr-xr-x，让普通用户能改自己的密码
> ```
> **三种特殊权限**：SUID=4（u+s）、SGID=2（g+s）、Sticky=1（o+t，如 /tmp 的 1777）。

## 第152题 vim中把所有的a替换为b，写出命令。

:% s#a#b#g

> **补充说明**：
>
> ```bash
> :%s#a#b#g
> ```
> **拆解**：
>
> | 片段 | 含义 |
> | --- | --- |
> | `:` | 进入底行模式 |
> | `%` | 表示**所有行**（范围，也可用 `1,10` 指定 1~10 行） |

> ```

## 第153题 本地IP为10.0.0.100，需要/root/a.sql传到IP为60.250.1.170,ssh端口为25535的/data/目录下，写出命令（scp）

scp /root/a.sql root@60.250.1.170:25535/date

> **更正**：原题答案 `scp /root/a.sql root@60.250.1.170:25535/date` **格式错误**（端口不能用 `IP:端口` 写在路径里，且 `/date` 应为 `/data`）。
>
> **正确写法**（scp 指定端口用**大写 `-P`**）：
>
> ```bash
> scp -P 25535 /root/a.sql root@60.250.1.170:/data/
> ```
> **要点**：
> - **scp 用 `-P`（大写）指定端口**，ssh 用 `-p`（小写）——**这是常见易错点**！
> - 目标路径 `/data/` 前用冒号连接主机与路径
> - 传目录加 `-r`
>
> ```bash
> # 传目录
> scp -P 25535 -r /root/data/ root@60.250.1.170:/data/
> # 反向：从远程拉回来
> scp -P 25535 root@60.250.1.170:/data/a.sql /root/
> ```
> **补充**：大量文件/增量同步建议用 `rsync -avz -e 'ssh -p 25535'`，比 scp 更高效。
