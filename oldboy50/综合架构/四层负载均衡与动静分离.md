# 四层负载均衡与动静分离

## 一、先把概念理清楚

### 1. 负载均衡按 OSI 层级划分
| 层级 | 代表 | 转发依据 |
| --- | --- | --- |
| **四层**（TCP 层） | LVS、Nginx stream、HAProxy | IP + 端口 |
| **七层**（HTTP 层） | Nginx、HAProxy | 协议（域名、URL、Header 等） |

> HTTPS 在七层看协议、四层看端口。

### 2. 常见负载均衡方案
- **F5**：硬件负载均衡（贵、性能强）。
- **LVS**：软件四层负载均衡。
- **HAProxy**：同时支持四层和七层。
- **Nginx**：1.9 之前只支持七层；1.9+ 通过 `stream` 模块支持四层。

### 3. Session 与会话保持
- 代码默认把 **Session 存在 Web 服务器本地**，多台 Web 之间不共享就会掉线。
- **会话保持（Session Sticky）**：`ip_hash`，同一 IP 固定打到同一台后端。
- **会话共享（Session Share）**：存到 Redis / MySQL，所有 Web 共用。
- **存客户端**：浏览器 **Cookie**（客户端保存）。

## 二、Nginx 四层负载均衡（TCP 端口转发）

> 需求：访问负载均衡的 `5555` 端口 → 实际连后端 web01 的 `22`（SSH）；访问 `6666` → 实际连后端 MySQL 的 `3306`。
> 前提：Nginx **1.9.0+** 编译时带 `--with-stream`（默认不编译）。

**四层代理只能写在 `main` 段（http 块之外）。**

```bash
# /etc/nginx/nginx.conf：在 events 下面、http 上面引入子配置
include  /etc/nginx/conf.c/*.conf;

mkdir -p /etc/nginx/conf.c

# /etc/nginx/conf.c/stream.conf
stream {
  # 1. 定义虚拟资源池
  upstream ssh {
    server 172.16.1.7:22;
  }
  upstream mysql {
    server 172.16.1.51:3306;
  }
  # 2. 调用虚拟资源池
  server {
    listen 5555;          # 访问 5555 → 转发到 ssh 池
    proxy_pass ssh;
  }
  server {
    listen 6666;          # 访问 6666 → 转发到 mysql 池
    proxy_pass mysql;
  }
}

nginx -t
systemctl restart nginx
netstat -lntp
```

验证：
```bash
# Windows Xshell 本地连接负载均衡 5555，实际连上的是 172.16.1.7 (web01)
[e:\~]$ ssh 10.0.0.5 5555

# 数据库连接工具 Navicat 连 lb02 的 6666 端口，实际是后端 MySQL
```

## 三、Nginx 七层负载均衡（HTTP 反向代理）

```bash
# /etc/nginx/conf.d/proxy.conf
upstream node {
  server 10.0.0.7;
  server 10.0.0.8;
}
server {
  listen 80;
  server_name nginx.bjstack.com;
  location / {
    proxy_pass http://node;      # 调用 node 主机池
    include proxy_params;
  }
}

# /etc/nginx/proxy_params（代理到后端时携带的请求头与超时配置）
proxy_set_header Host $http_host;
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_connect_timeout 30;
proxy_send_timeout  60;
proxy_read_timeout  60;
proxy_buffering on;
proxy_buffer_size 32k;
proxy_buffers 4 128k;
```

给 web01/web02 设置不同的 `index.html`（标记 1 和 2），重启后访问可看到请求被轮询分发。

```bash
nginx -t
systemctl restart nginx

# Windows hosts 解析
10.0.0.5   nginx.bjstack.com
# 浏览器访问 http://nginx.bjstack.com/
```

## 四、七层代理转四层代理（注意重复 stream 报错）

有时需要把七层入口再转发到后端的 SSH（不同端口对应不同主机）：

```bash
# /etc/nginx/conf.c/stream2.conf
stream {
  upstream ssh_web_one {
    server 10.0.0.7:22;
  }
  upstream ssh_web_two {
    server 10.0.0.8:22;
  }
  server {
    listen 2244;
    proxy_pass ssh_web_one;   # 2244 → web01
  }
  server {
    listen 2245;
    proxy_pass ssh_web_two;   # 2245 → web02
  }
}
```

⚠️ **报错**：`nginx: [emerg] "stream" directive is duplicate`
原因：之前已有 `stream.conf`，一个 Nginx 只能有一个 `stream {}` 块。把旧的 `stream.conf` 关掉（改名/移走）即可。

```bash
nginx -t
systemctl restart nginx
netstat -lntp
# Windows Xshell：ssh 10.0.0.5 2244 连 web01；2245 连 web02
```

## 五、Nginx 动静分离

**什么是动静分离**：通过中间件把「动态请求」和「静态请求」分开处理，减少不必要的请求消耗和延时。
**好处**：即使动态服务挂了，静态资源（图片等）依然可访问。本质是 **SOA 松耦合**思想。

| CentOS7.4 | Tomcat | 10.0.0.7 |

### 1. 在 10.0.0.7 上准备静态资源
```bash
mv /etc/nginx/conf.d/default.conf /tmp/

server {

    root /soft/code/images;

systemctl restart nginx

# Windows hosts：10.0.0.7 images.oldboy.com
# 浏览器访问 http://images.oldboy.com/nginx.png
```

### 3. 在 10.0.0.5（proxy）整合动静分离
```bash
cat > /etc/nginx/conf.d/ds_proxy.conf <<EOF
upstream static {
  server 10.0.0.7:80;
}
upstream java {
  server 10.0.0.7:8080;
}
server {
  listen 80;
  server_name ds.oldboy.com;
  location / {
    root /soft/code;
    index index.html;
  }
  location ~ .*\.(png|jpg|gif)$ {     # 静态 → static 池(80)
    proxy_pass http://static;
    include proxy_params;
  }
  location ~ .*\.jsp$ {               # 动态 → java 池(8080)
    proxy_pass http://java;
    include proxy_params;
  }
}
EOF

cat > /etc/nginx/proxy_params <<EOF
# 发往后端的请求头：host、客户端真实 IP
proxy_set_header Host \$http_host;
proxy_set_header X-Real-IP \$remote_addr;
proxy_set_header X-Forwarded-For \$proxy_add_x_forwarded_for;
# 代理到后端的连接/响应/返回超时
proxy_connect_timeout 30;
proxy_send_timeout 60;
proxy_read_timeout 60;
# 代理缓冲区
proxy_buffering on;
proxy_buffer_size 32k;
proxy_buffers 4 128k;
EOF

nginx -t
systemctl restart nginx

# Windows hosts：10.0.0.7 ds.oldboy.com
# 浏览器访问：
#   http://ds.oldboy.com/java_test.jsp   （动态，Tomcat 处理）
#   http://ds.oldboy.com/nginx.png       （静态，Nginx 处理）
```

## 六、Session 与 Cookie（面试必背）

### 1. 一句话大白话
- **Cookie**：存在**浏览器（客户端）**上的一小段文本数据（键值对）。
- **Session**：存在**服务器**上的用户数据（文件 / 内存 / Redis）。

### 2. 核心区别（生产 / 面试必背表格）
| 对比项 | Cookie | Session |
| --- | --- | --- |
| 存储位置 | 客户端（浏览器本地） | 服务器端（内存/文件/Redis） |
| 存储大小 | 很小（单站点最多约 20 个，每个 ≤4KB） | 几乎无限制（存用户信息、登录状态） |
| 安全性 | 低（明文、可篡改、可见） | 高（服务器存储，用户无法直接修改） |
| 生命周期 | 可长期保存（设过期时间） | 默认浏览器关闭即失效 |
| 性能压力 | 无服务器压力 | 大量用户会占用服务器资源 |
| 依赖关系 | 独立存在，不依赖 Session | **必须依赖 Cookie** 传递 Session ID |
| 适用数据 | 非敏感（记住账号、主题、购物车） | 敏感（登录状态、用户信息、权限） |

### 3. 工作流程（Nginx+PHP 登录场景）
1. 用户首次访问，服务器**创建 Session**，生成唯一 `Session ID`。
2. 服务器把 `Session ID` 写进 **Cookie**，下发给浏览器。
3. 浏览器自动保存该 Cookie（只存 Session ID）。
4. 后续每次请求，浏览器**自动把 Cookie 带给服务器**。
5. 服务器用 Cookie 里的 `Session ID` 找到对应的用户 Session 数据。

### 4. 最关键的联系（90% 新手不懂）
> **Session 本身不能传输，必须靠 Cookie 携带 Session ID。**

- Cookie 存的是：`PHPSESSID=abc123`（一串随机码）。
- Session 存的是：`{"username":"admin","login":true}`（真实用户数据）。

### 5. 生产高频问题
1. **禁用浏览器 Cookie 会怎样？**
   Session 直接失效（无法传递 Session ID），需用 URL 重写兼容（很少用）。
2. **Nginx 集群 / 多服务器时 Session 怎么办？**
   默认 Session 存单台会掉线。**解决方案：用 Redis 统一存储 Session**（生产标准）。
3. **为什么登录状态用 Session 不用 Cookie？**
   Cookie 可被用户篡改（把 `login=false` 改成 `true` 直接越权）；Session 在服务器端，用户无法修改，**更安全**。

## 七、常见面试题

1. **四层负载均衡和七层负载均衡有什么区别？**
   四层基于 IP+端口转发（LVS/Nginx stream/HAProxy），速度快、不解析内容；七层基于应用协议（域名/URL/Header）转发（Nginx/HAProxy），可做得更精细。

2. **Nginx 怎么做四层负载均衡？有什么限制？**
   用 `stream` 模块（需 1.9+ 且编译带 `--with-stream`），配置写在 `main` 段、http 块之外；且一个 Nginx 只能有一个 `stream {}` 块，重复定义会报 `duplicate` 错误。

3. **什么是动静分离？有什么好处？**
   把静态资源（图片/JS/CSS）和动态请求（JSP/PHP）分开由不同后端处理。好处：静态走 Nginx 高性能、动态挂了不影响静态、减轻后端压力。

4. **多台 Web 服务器时如何保持用户登录状态？**
   方案：① `ip_hash` 会话保持（同 IP 固定后端）；② Session 共享存 Redis（推荐）；③ 把 Session 存客户端（不安全，少用）。

5. **Cookie 和 Session 的区别？Session 为什么依赖 Cookie？**
   见上文表格。Session 数据在服务端，但服务器要靠客户端带回的 `Session ID` 来找回数据，而 Session ID 通常放在 Cookie 里传递。

6. **如果浏览器禁用了 Cookie，Session 还能用吗？**
   默认不能（拿不到 Session ID）。退路是 URL 重写把 Session ID 拼在链接里，但已基本不用。
