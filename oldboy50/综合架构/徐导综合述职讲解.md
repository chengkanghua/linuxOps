# 徐导综合述职讲解

> 综合架构五层模型：**自动化配置** → **监控** → **安全** → **日志** → **备份**，外加**数据库**与**自动化上线**。面试时建议边画图边讲，按"用户访问流程"串起来，对方穿插提问时逐个解答。

## 一、原始网站架构

用户浏览器输入 `www.oldboyedu.com`：
1. DNS 解析得到真实 IP
2. TCP 三次握手建立连接，发起 HTTP 请求
3. 请求先到**防火墙**（按规则放行）
4. 再到**负载均衡**（本身不处理，转发给真实 Web 节点）
5. Web 节点处理请求：静态请求直接返回；动态请求经 PHP 模块通过 `mysqli` 函数查数据库

## 二、架构调整与优化

### 1. 负载均衡高可用
原负载均衡无高可用，挂掉则业务全断 → 引入 **Keepalived** + 备节点，VIP 地址漂移消除单点。

### 2. 图片/附件上 CDN
原所有图片附件统一放存储服务器，访问量大时网页极慢 → 将存储内容同步到**阿里云/腾讯云/七牛云存储**并接入 CDN，代码里图片地址 `www.oldboy.com/1.jpg` 改为 `cdn.oldboy.com/1.jpg`（JS/CSS/MP4 同理），全站静态资源走 CDN。

### 3. 自动化搭建集群
不可能逐台装机 → 用 **Ansible/SaltStack** 批量拉起集群：Playbook + YAML，配置推送常用模块 `yum`、`copy`、`service`、`template`（Jinja2 渲染）。

### 4. 代码自动化部署
配置类可用 Ansible 推送，但**业务代码**用 **GitLab + Jenkins** 实现 PHP 代码自动化部署（开发者提交代码，Jenkins 定时/触发自动构建发布）。

### 5. 监控 Zabbix
机器多了无法 7×24 盯盘 → 引入 **Zabbix**：
- **系统层**：CPU 负载、内存、IO、磁盘使用率，用 `zabbix-agent` + 官方 Linux OS 模板（内建触发器阈值偏低，已调高）
- **应用层**：负载均衡、Web、数据库、NFS 自带状态页，用脚本取值做监控
- **Web 监测**：保证网站时刻可打开
- **自动注册**：新机装 agent 自动入监控并关联模板，免手动添加
- **分布式**：机器分布在北京/湖北/上海三套集群 → 用 **Zabbix-Proxy** 做分布式监控

### 6. 安全
- 系统层面：重要服务器**无公网 IP**，仅负载均衡/管理机有公网
- 应用层面：数据库账号密码不简单；内网机通过 **JumpServer 跳板机**登录（实现日志审计），四层 **firewalld** 只允许 80/443，22 端口仅运维经跳板连接
- Web 应用安全：SQL 注入、程序漏洞、DDoS → 引入**牛盾云**厂商防护
- 云主机安全组关闭多余端口，用云骑士防 DDoS/SYN 攻击

### 7. 日志
各节点产生大量日志（负载/Web/MySQL）→ 引入 **ELK** 或**日志易**：
- 日志易：各节点配其对端地址端口，由厂商分析
- ELK：各节点装 **Filebeat** 采集 → 发到 **Elasticsearch** 索引 → **Kibana** 展示（中间用 Redis/Kafka 消息队列削峰）
- 流程：`收集 → 存储 → 展示`，结构与 Zabbix 相似

### 8. 备份
- 仅需备份 **Ansible 上的配置** 与 **数据库**
- Ansible 配置即集群"源"，定期备份 Ansible 机即可；若 Ansible 损坏，换新机批量推送公钥即可恢复 Playbook（Ansible 可移植性强不挑客户端）

### 9. 数据库
- 早期 **主从**（主库读写，从库备份）
- 读写分离可由**程序开发人员**实现，或用中间件 **MyCat**（写走主库，读走多台从库）；读远多于写（新闻/博客/论坛/视频）
- 从库之上做 **MHA 高可用**（被问到须能讲清细节）

## 三、五层架构模型总结

| 维度 | 做法 |
| --- | --- |
| **架构** | LNMP（PHP）；后加 LNMT（Tomcat）；两台七层负载 + 20 台 Web + 3 台数据库 + 2 台备份（本地+云） |
| **监控** | Zabbix 系统/应用/Web 监控 + 自动注册 + Proxy 分布式 |
| **日志** | ELK/日志易，分析访问日志、错误日志、安全日志中的异常与攻击 |
| **安全** | firewalld 限端口 + 跳板机审计 + 牛盾 Web 防护 + 云安全组 |
| **优化** | 配参差不齐加权重；Keepalived 地址漂移消单点；一主两从 + MHA + MyCat 读写分离 |
| **备份** | 高容量备份机存重要数据与配置；客户端脚本+定时任务推送，定期清理旧数据 |
| **自动化** | Ansible 批量管理集群，统一编组统一管控，提升效率 |

## 四、GitLab + Jenkins 持续集成

- **GitLab**：代码仓库，管理代码
- **Jenkins**：自动化服务器，跑构建/测试/部署任务
- 流程：开发者提交代码到 GitLab → Jenkins 按计划/触发自动构建、测试、发布，提升集成发布效率

## 面试题（综合架构）

1. **你们的网站整体架构是怎样的？**
   DNS→防火墙→负载均衡(Keepalived 高可用)→Web(LNMP/LNMT)→数据库(主从+MHA+MyCat)；静态资源走 CDN；自动化用 Ansible + GitLab/Jenkins；监控 Zabbix；日志 ELK；安全 firewalld+跳板机+牛盾。

2. **为什么引入 Keepalived？**
   消除负载均衡单点，VIP 漂移实现主备切换，避免负载挂掉业务全断。

3. **图片慢怎么解决？**
   存储内容同步到云存储并接 CDN，代码里资源 URL 改为 CDN 域名，全站静态资源走 CDN 加速。

4. **自动化上线怎么做？**
   配置类用 Ansible Playbook 推送；业务代码用 GitLab + Jenkins 实现持续集成自动发布。

5. **监控怎么做的？**
   Zabbix 系统/应用/Web 三层监控，配自动注册免手动加主机，多地区用 Proxy 分布式；模板阈值按需调整。

6. **安全层面有哪些措施？**
   内网机无公网 IP，仅负载/管理机有公网；firewalld 限 80/443；跳板机审计登录；牛盾防 Web 攻击；云安全组关多余端口。

7. **数据库高可用与读写分离？**
   一主两从，MHA 做故障切换高可用，MyCat 中间件实现读写分离（写主库、读从库）。

8. **日志方案？**
   Filebeat 采集→消息队列(Redis/Kafka)→Elasticsearch 存储→Kibana 展示；或日志易 SaaS。

9. **备份策略？**
   备份 Ansible 配置（集群源）与数据库；Ansible 机可移植，损坏换新机推公钥即可恢复；客户端脚本+定时任务推送并定期清理。
