# 修改文件/目录的属组和用户

```bash
Linux 修改文件 / 目录 属主（用户） + 属组 命令
# 1. 仅修改 属主（用户）
chown [用户名] [文件/目录]
# 2. 同时修改 属主 + 属组（最常用！）
chown [用户名]:[组名] [文件/目录]

# 3. 递归修改（目录 + 目录下所有子文件/子目录）
chown -R [用户名]:[组名] [目录]
# 兼容写法：用户名.组名 和 用户名:组名 效果完全一样


实战示例  
# 把 a.txt 的属主改成 root
chown root a.txt

# 把 a.txt 的属主改为 www，属组改为 www
chown www:www a.txt

递归修改目录（工作最常用）
# 把 /var/www/html 目录及里面所有内容，属主/属组都改为 nginx
chown -R nginx:nginx /var/www/html
```

# 修改文件 / 目录的访问权限

## 一、先搞懂 3 个核心概念（基础必看）

### 1. 权限针对的 3 类用户（谁能访问？）

<code>u</code> → user 文件**属主**（所有者）

<code>g</code> → group 文件**属组**（所属组）

<code>o</code> → other 其他用户

<code>a</code> → all 所有用户（u+g+o）

### 2. 权限的 3 种类型（能做什么？）

<code>r</code> → read 读权限

<code>w</code> → write 写权限

<code>x</code> → execute 执行权限

### 3. 权限 **数字对应值**（最核心！）

| **权限** | **符号** | **数字** | **含义** |
| :--- | :--- | :--- | :--- |
| 读 | r | 4 | 查看文件内容 / 浏览目录 |
| 写 | w | 2 | 修改 / 删除文件 / 创建文件 |
| 执行 | x | 1 | 运行脚本 / 进入目录 |

**数字相加 = 最终权限**

例：<code>rwx = 4+2+1=7</code>，<code>rw-=4+2=6</code>，<code>r-x=4+1=5</code>

## 二、🔥 最常用：数字权限法（工作首选）

```plain
chmod [3位数字权限] 文件/目录
```

3 位数字分别对应：**属主 (u) + 属组 (g) + 其他 (o)**

### 最常用 5 组权限（背会这 5 个够用 99%）

| **数字** | **权限** | **适用场景** |
| :--- | :--- | :--- |
| 755 | rwxr-xr-x | **目录默认权限**（可进入、可读取） |
| 644 | rw-r--r-- | **文件默认权限**（可读写、只读） |
| 777 | rwxrwxrwx | 开放所有权限（慎用，仅测试用） |
| 600 | rw------- | 私密文件（仅自己能读写，如密钥） |
| 700 | rwx------ | 私密目录（仅自己能访问） |

### 实战示例

```bash
# 1. 给文件设置 644（最常用文件权限）
chmod 644 a.txt

# 2. 给目录设置 755（最常用目录权限）
chmod 755 /data

# 3. 给脚本加执行权限
chmod 755 test.sh

高频用法：递归修改权限
给目录 + 目录下所有子文件 / 子目录统一改权限
# 把 /www 目录及所有内容 权限设为 755
chmod -R 755 /www
```

## 三、灵活用法：**符号权限法**

语法

```bash
chmod [用户][+-=][权限] 文件/目录

+：添加权限
-：移除权限
=：直接赋值权限

实战示例

# 给属主添加执行权限
chmod u+x test.sh

# 给其他用户移除写权限
chmod o-w a.txt

# 所有用户添加读权限
chmod a+r a.txt

# 直接设置属组为只读
chmod g=r a.txt


```

## 四、关键区别：文件 vs 目录 权限含义

新手最容易错，一定要记：

1. **文件**
   * <code>r</code>：查看内容
   * <code>w</code>：修改 / 删除
   * <code>x</code>：**执行脚本 / 程序**
2. **目录**
   * <code>r</code>：查看目录里的文件列表
   * <code>w</code>：创建 / 删除 / 重命名文件
   * <code>x</code>：**进入目录（cd）**

目录**必须有 x 权限**，否则无法进入！



# Web 服务（Nginx/Tomcat）标准权限

结合 <code>chown</code> + <code>chmod</code>，一键修复网站权限：

```bash
# 1. 修改归属
chown -R nginx:nginx /usr/share/nginx/html

# 2. 目录权限 755
chmod -R 755 /usr/share/nginx/html

# 3. 文件权限 644
find /usr/share/nginx/html -type f -exec chmod 644 {} \;




```

useradd bz

chmod 660 text1

# 8. 关键补充：锁定父目录/book，防止其他同学进入浏览
chown bz:zy /book

文件 text1 权限：660

其他人：--- 无权读、无权写、无权进
目录 /book 权限：750
属主：可进入、可查看、可修改目录

## 二。 你有一个隐私日记本book， 日记本中有N多文件 text1/text2/text3你有3个闺蜜可以修改此文件，其他小伙伴不可修改，不可读。

```bash
# 1. 创建目录 + 进入 + 批量创建3个文件 → 正确
mkdir /book
cd  /book
touch text{1..3}.txt

# 2. 创建组 + 3个闺蜜用户 + 加入组 → 正确
groupadd zy
useradd gm1
useradd gm2
useradd gm3
gpasswd -M gm1,gm2,gm3 zy  

# 3. 递归修改 /book 及所有文件的 属组 为 zy → 正确（只改组，完美）
chown -R :zy /book/   

# 4. 批量给文件设置 660 → 正确！
# 权限：属主rw-  |  组内rw-  |  其他人---
# 闺蜜在组里 → 能读能改；其他人 → 无任何权限
chmod 660 /book/*   

# 5. 给目录设置 750 → 核心正确！
# 目录权限：属主rwx | 组内r-x | 其他人---
# 作用：其他人**根本进不去 /book 目录**，彻底隔绝
chmod 750 /book    
```

权限总结：

rwx

r   针对目录		能够看到目录下的内容， 也就是说能够ls查看目录下的内容

```
针对文件		能够看到文件内的内容，也就是说能够使用cat 查看文件内的内容

```

w  针对目录  如果目录有w权限，就可以删除目录下的内容

```
针对文件	 如果文件有w权限，就可以修改文件内的内容，但是目录没有写权限，文件不能删除。
```

备注： 当目录有w权限，目录下的文件有w权限，这时才能修改并能删除。

```
    x  针对目录	能够通过 cd  目录名 进入到目录里面，如果没有x 权限，就不能通过cd 目录名 进入到目录里面。

针对文件  当文件是脚本语言或java/c等，文件赋予执行权限才有用途，否则文件的执行权限没有用
```
