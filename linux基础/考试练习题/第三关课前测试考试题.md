```bash
 1 加载 MBR 主引导记录
 2 启动 GRUB 引导菜单
 3 加载 Linux Kernel（内核）
 4 启动 systemd 进程（系统 1 号进程）
 5 systemd 启动系统服务 / 运行级别
 6 显示登录界面

🎯 2 分钟口述完整版（照着说就行）
1 电脑开机后，BIOS 进行硬件自检，读取硬盘的MBR 主引导记录；
2 MBR 加载GRUB 引导菜单，让我们选择要启动的内核；
3 GRUB 加载Linux 内核（Kernel），内核初始化硬件、挂载根分区；
4 内核启动systemd 进程（PID=1，系统第一个进程）；
5 systemd 按照配置启动系统服务、设置运行级别；
6 最后启动终端 / 图形化界面，显示登录界面，开机完成。
```



# 2. 描述 linux  下软链接和硬链接的区别。（记时 2  分钟）
```bash
Linux 软链接 vs 硬链接 区别（2 分钟标准版）
软链接和硬链接的核心区别，本质是对文件的引用方式不同：

软链接（符号链接）
相当于 Windows 的快捷方式，是一个独立的新文件。
它拥有独立的 inode 号，内部只存储原文件的路径，不存储真实数据。
支持跨文件系统创建，也可以给目录创建软链接。
一旦原文件被删除，软链接就会变成红色失效文件，无法使用。

硬链接
相当于文件的另一个入口 / 别名，不是独立文件。
它和原文件共用同一个 inode 号，系统认为它们就是同一个文件。
不支持跨文件系统，也不允许给目录创建硬链接（系统限制）。
即使原文件被删除，硬链接依然可以正常访问数据，只有当所有硬链接和原文件都被删除，文件数据才会真正被释放。


一句话核心总结
软链接 = 快捷方式（独立文件、存路径、可跨区、删原文件失效）
硬链接 = 文件别名（同 inode、同文件、不跨区、删原文件不受影响）
```

# 3.描述 linux shell 中单引号、双引号及不加引号的简单区别 （记时 时 2  分钟）
```bash
Linux Shell 中，单引号、双引号和不加引号的核心区别，是对变量、特殊字符、空格的解析规则不同：
单引号 ' '
属于强引用，特点是原样输出。引号内的所有内容，包括变量 $、转义符、特殊符号、空格，都会被当作普通文本，不做任何解析和转义，所见即所得。
双引号 " "
属于弱引用，特点是解析变量和特殊转义字符。引号内的普通字符原样输出，$ 变量、\ 转义符会被正常解析执行，同时会保留空格，不会把字符串分割成多个参数。
不加引号
属于自动解析模式，会解析 $ 变量和特殊字符，但遇到空格、制表符会自动分割字符串，把一整段内容拆分成多个命令参数，容易引发参数错误，稳定性最差。

极简记忆口诀
单引号：全原样，不解析
双引号：解变量，保空格
不加引号：解变量，会分割


```

## 问题 4:打扰是工作中司空见惯的事。过去你用什么办法来对付工作中的打扰（考察时间观
念）？

解答：

```bash
在工作中我会以「保证核心工作效率为前提，兼顾团队协作」为原则，通过分类管理、集中处理、划定边界的方式应对打扰，具体做法如下：
给任务和打扰分优先级，抓核心放次要
我会按照工作轻重缓急划分：如果是紧急核心问题（比如服务器宕机、业务故障、线上报错），我会立即处理；如果是非紧急咨询、闲聊、常规琐事，我会礼貌告知对方当前正在处理核心工作，约定时间统一回复，不被碎片化打扰打断思路。
划定专属专注时间，集中处理干扰
处理需要高度专注的工作（如写脚本、做架构规划、排查复杂故障）时，我会预留整块的专注时间，暂时关闭非必要的消息提醒；把日常的咨询、沟通、琐事集中在固定时段统一处理，既不耽误同事的需求，也能保证核心工作的连贯性。
沉淀通用方案，从源头减少无效打扰
针对同事频繁咨询的共性问题（如权限申请、环境使用、常用命令、操作流程），我会整理成文档共享，让大家自助查阅，从源头减少重复、低效的打扰；复杂问题统一用语音 / 会议沟通，避免碎片化文字来回拉扯。
礼貌划定边界，高效沟通
遇到非紧急打扰时，我会礼貌说明：“我现在正在处理 XX 核心任务，15 分钟后找你详细沟通”，既不得罪同事，也能守住自己的工作节奏；同时做到不拖延、不推诿，约定的时间准时响应，保证团队协作顺畅。
总结（收尾金句）
我的核心方法是：急事优先处理，琐事集中处理，源头减少无效打扰。在保证团队协作的同时，最大化提升工作效率，确保核心任务高质量完成。


```

## kill 命令和 ps 命令常用方式
```bash
kill 命令的核心：向进程发送信号，实现关闭、重启、强制杀死进程，

#kill -l
15	SIGTERM	默认信号，优雅关闭进程（允许进程保存数据、清理资源）	首选
9	SIGKILL	强制杀死进程（暴力终结，无法拦截，可能丢数据）	顽固进程用
1	SIGHUP	重启进程 / 重读配置文件（不中断服务，热重载）	服务重载用

# 直接跟pid 默认15信号
kill 1234
#强制杀死进程（杀卡死 / 顽固进程，高频）
kill -9 1234
#重启 / 重载服务配置
kill -1 1234

killall：按进程名杀死所有同名进程
# 杀死所有 nginx 进程
killall nginx
# 强制杀死
killall -9 nginx
# pkill 同killall
pkill nginx
pkill -9 nginx

ps 用于查看系统进程状态
1. ps aux （最常用，BSD 格式）
2. ps -ef （常用，System V 格式）
参数说明
a：所有用户的进程
u：显示用户、CPU、内存等资源占用
x：显示无终端的进程（后台进程）
e：显示所有进程（同 a）
f：完整格式，显示父进程 PPID

按 CPU 使用率降序 排序
ps aux --sort=-%cpu
2. 按 内存使用率降序 排序
ps aux --sort=-%mem

VSZ （Virtual Size） 虚拟内存大小
RSS （Resident Set Size） RSS （Resident Set Size）
VSZ = 虚拟内存（吹牛皮说要用多少）
RSS = 物理内存（实际真用了多少）

```
