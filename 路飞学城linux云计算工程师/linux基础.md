# 第一篇 · 认识 Linux 与运维岗位

## 一、Linux 是什么

先想象几个新手常有的对话：

> "Linux？听说是一个操作系统，好用吗？"
>
> "我也不知道呀，和 Windows 有什么区别？我能在 Linux 上玩 LOL 吗？"
>
> "别提了，我用过 Linux，就是黑乎乎一个屏幕，鼠标也不能用，不停地敲键盘，手指头都给我磨破了！"

或许你也是这么想的。

其实答案非常简单：**Linux 就是一个操作系统**，和你熟悉的 Windows XP / 7 / 10、macOS 是同一类东西。它负责管理整台电脑的硬件和软件，只是默认大多以"黑底命令行"的方式和人打交道，看起来有点吓人而已。

> 💡 新手最容易把 Linux 想象成某种很高级、很难的软件。放下这个心理负担——它只是一个操作系统，和 Windows 平级，不是什么高深的东西。

## 二、互联网发展简史

### Linux 诞生的年代

1991 年，芬兰大学生**林纳斯·托瓦兹（Linus Torvalds）**写出了 Linux 内核的第一个版本。那一年：

- 还没有满街的微信支付、支付宝；
- 你的女朋友还不知道淘宝网；
- 同学朋友之间还没有 QQ、微信这些联系方式；
- 互联网基本只出现在美国。

### 中国互联网的起点

- **1994 年 4 月 20 日**，中国通过一条 64K 的国际专线接入国际互联网，这一天被看作中国互联网的诞生之日。
- 1997 年 6 月，丁磊创立网易
- 1998 年 2 月，张朝阳成立搜狐
- 1998 年 11 月，马化腾、张志东等五位创始人创立腾讯
- 1998 年 12 月，王志东创立新浪

中国互联网就这样从无到有、从小到大、从跟随到领先。

### 互联网的一分钟

如今互联网一分钟会发生什么？有大数据公司做过有趣的统计（数据为早期统计，感受一下量级即可）：

- 滴滴打车：一分钟有 1388 辆出租车、2777 辆私家车被叫车服务
- 微信：一分钟有 395833 人登录，19444 人进行视频或语音聊天
- 视频网站：一分钟有 625000 部视频被观看
- 微博：一分钟发出 64814 条信息，其中 50925 条含照片、1891 条含视频、498 条含音乐
- 百度：一分钟有 4166667 个搜索请求
- 淘宝 / 天猫：一分钟有 774 个人下单完成购买

### 互联网给生活做了"减法"

从追星、阅读、社交，到恋爱、购物、订票，互联网把这些事一件件搬到了线上：

## 三、Linux 与互联网：运维在背后做什么

我们每天享受互联网的便利，却很少有人知道"Linux 是什么""运维是什么"。下面讲两个真实的故事。

### 微博背后的运维

新浪微博曾发生过这样的事：某位运维工程师结婚当天，明星突然爆出热点新闻，网友疯狂转发评论，流量瞬间暴涨导致**服务器宕机**。运维工程师们只能立刻放下手头的事去抢救服务器，连婚礼都得缓一缓。当时网上还流传着运维的吐槽：

> "各位明星爆新闻前能不能行行好，跟我们运维的小伙伴打个招呼？随便你怎么上热搜，只要别把服务器搞挂就行。"

### 淘宝背后的运维

"双十一"是网购用户的大日子，大量商品打折、用户量暴增。对淘宝背后的技术团队来说，这是一场必须打赢的硬仗——要保证网站正常运转、保证用户能顺畅下单付款。当天成交额以亿、百亿为单位往上跳，背后全靠服务器和运维撑着。

### 运维人员的三大核心职责

不管是微博还是淘宝，运维的核心目标其实就三句话：

1. **网站数据不能丢**
2. **网站要能 7×24 小时运转**
3. **访问速度要快，提升用户体验**

## 四、Linux 的行业地位

Linux 和 Windows 一样，本质都是操作系统。区别在于：

- **Windows** 更多出现在日常生活中，面向个人办公、影音娱乐，大家都熟悉。
- **Linux** 主要用在**企业端（服务器）**，由专业的 Linux 运维工程师使用。

我们用的每一个互联网应用——聊天、支付、看视频、网购——看似简单，背后都有极其复杂的数据请求和响应。在腾讯、新浪、百度、苹果等公司的机房里，是数以千万计的 Linux 服务器在处理这些请求。

### 为什么说"打开 Linux 的大门，才算合格的软件工程师"

- 根据 W3Techs 的统计，**服务端操作系统中 Linux 占比约 70% 以上**（数据随年份变化，总之是绝对主流）。
- 手机系统主要是 Android 和 iOS，而 **Android 正是基于 Linux 内核**开发的。
- 大数据、云计算、容器、人工智能这些热门技术，几乎都构建在 Linux 之上。

Linux 更像一个完整、繁荣的生态，主流 IT 技术基本都优先在 Linux 上开发：

| 方向 | 代表技术 |
| --- | --- |
| 数据库 | MySQL、PostgreSQL |
| Web 服务器 | Nginx |
| 大数据 | Hadoop、Spark |
| 消息队列 | Kafka |
| 虚拟化 | KVM |
| 容器 | Docker、Kubernetes |

这些软件在 Linux 上都能很方便地找到文档和资料，其他平台则远没有这么完善。使用 Linux 服务器的公司也遍布各行各业：互联网、出行、金融、直播、芯片……几乎所有技术公司都在用。

## 五、Linux 与 Windows 的区别

### 1. 免费与收费

- Windows：正版需要付费（例如早期正版 Windows 10 官方售价约 ¥888）。
- Linux：**基本免费开源**。也正因为开源，更多人愿意钻研，而收费产品反而容易出现盗版。

### 2. 软件与支持

- **Windows**：软件数量多、体验好，但大部分是收费软件，由微软官方提供技术支持。
- **Linux**：大多是开源软件，用户可以自由修改、定制、发布；因为免费、缺少商业资金支持，个别软件的易用性可能差一些。

### 3. 安全与稳定

- **Windows**：需要经常打补丁，装了各种杀毒软件、安全卫士仍可能中毒。
- **Linux**：安全问题少得多，默认权限设计严谨，一般不需要装杀毒软件。这也是它能长期稳定跑在服务器上的重要原因。

### 4. 使用习惯

- **Windows**：主要靠图形界面，鼠标 + 键盘完成一切，上手简单。
- **Linux**：既有图形界面（带桌面环境的发行版），也可以完全用命令行操作。纯命令行下新手会觉得困难，但**学会之后效率极高**，而且特别适合远程管理服务器。

### 5. 应用领域

- **Linux**：你在 Windows 上访问的百度、谷歌、淘宝、QQ、视频网站，后台都是成千上万台 Linux 服务器在做数据处理和运算。
- **Windows**：适合运行各种大型游戏和日常桌面软件，Linux 上的原生游戏则很少。

> 📌 一句话记忆：**Windows 赢在桌面和娱乐，Linux 赢在服务器和稳定。**

## 六、Linux 难学吗

Windows 美观、便捷，在个人电脑上深入人心；而 Linux 靠开源、稳定、安全、灵活，占据了服务器端的位置。

普通用户从 Windows 转到 Linux 确实会不适应——因为你曾经习惯的"点点点"，在服务器上全都变成了**命令行**。但这并不意味着难，它只是一项需要**系统地、全面地学习**才能掌握的技能。命令数量虽然看起来很多，实际日常高频使用的也就几十个，用熟了会非常自然。

Linux 运维是一门**实践性很强**的学科，需要大量动手练习，亲手在命令行里敲、去感受，而不是只看理论。

## 七、运维岗位方向与待遇

### 运维是做什么的

运维工程师的职责是：**保障服务器稳定运行、网站 7×24 小时正常运转；负责 Linux 服务器的部署；持续学习运维技术；用各种手段解决线上问题。** 它是一门集网络、数据库、Web、运维、安全等知识于一体的综合性岗位。

### 运维的细分方向

运维涉及的领域很宽，可以往多个方向深入：

- 系统运维
- 网络运维
- 安全运维
- 数据库运维
- 大数据运维
- 运维开发（DevOps / SRE）

### 薪资待遇

招聘网站（如猎聘）上对 Linux 运维岗位有过统计（**以下为早期历史数据，仅作了解，实际随年份、城市、能力差别很大**）：

- 月均薪资约 ￥11000+，薪资样本主要分布在 10K～20K 区间；
- 按工作年限：1 年以下约 1 万，1～3 年约 1.2 万，年限越长整体越高；
- 高级、专家或带开发能力的运维（SRE / 运维开发）薪资会明显更高。

> 💡 真正决定薪资上限的，不是"会敲多少命令"，而是能不能解决复杂的线上问题、能不能做自动化和架构。这也是课程后面会一路深入的原因。

## 八、我适合学 Linux 吗 · 如何学习 · 未来

### 哪些人适合学

- 零基础纯小白
- 计算机爱好者
- 已经在 IT 行业、想往运维 / 云计算方向发展的人

运维不像纯开发那样需要很强的算法和逻辑思维，它更看重**细心、严谨的工作态度**，以及持续学习和动手实践。

### 如何快速学习

成功没有捷径。如果真要说有捷径，那就是**走一条正确的路、少走弯路，加上自我驱动、坚持练习**。一般的成长路线大致是：

1. Linux 运维基础
2. 高级核心基础知识（网络、服务、存储等）
3. 中小规模集群项目实战
4. 大规模服务器集群实战
5. Shell 编程
6. 数据库 MySQL 与 NoSQL
7. 云计算与容器（Docker、Kubernetes）
8. 自动化开发、大数据、DevOps 等进阶方向

### 运维的未来

在大数据、人工智能、容器云时代，运维已经是任何一家技术公司都必须依赖和投入的核心部门：

- **容器化**让应用交付更快、创新更持续、运维更高效；
- **云计算 / IaaS**让企业不必再自己费劲维护机房和托管服务器；
- **DevOps**打通了开发（Dev）和运维（Ops），让软件能够更快速、更频繁、更可靠地交付。

# 第二篇 · 计算机基础

## 九、电脑：辅助人脑的工具

现在的人们几乎无时无刻不在使用电脑：台式机、笔记本、平板电脑、智能手机……这些都算"电脑"。

那"电脑/计算机"的准确定义是什么？

> **计算机是这样一种设备：接受使用者输入的指令和数据，经过中央处理器（CPU）的数学与逻辑运算，产生或存储成有用的信息。**

所以只要具备**输入设备**（键盘、触屏等）和**输出设备**（屏幕、打印机等），能够产出有用信息，它就是一台计算机。

按这个定义，下面这些都是计算机：

- 小卖部老板娘的计算器
- 不离手的手机
- 汽车上的车载导航 / GPS
- 自动取款机（ATM）
- 你正在用的笔记本
- 智能手表

> "哪有什么岁月静好，不过是有人替你负重前行。" 计算机就在背后默默执行着你交给它的任务。

## 十、用"人体"理解计算机

如果把计算机比作一个人，那么各个部件都能在身体上找到对应，这个比喻能帮你快速记住它们的分工：

| 计算机部件 | 对应人体 | 作用 |
| --- | --- | --- |
| **CPU** | 脑袋瓜子 | 负责思考、判断，控制全身的活动 |
| **内存** | 正在思考时的"短期记忆" | 临时存放外界刺激、正在处理的数据，供大脑判断 |
| **硬盘** | 长期记忆 / 回忆 | 把重要经验记录下来，以后还能再用 |
| **主板** | 神经系统 | 连接所有器官，把大脑的命令传递给手脚 |
| **显卡** | 脑中形成的影像 | 把眼睛看到的刺激转成图像呈现 |
| **各种外设** | 手、脚、皮肤、眼睛 | 负责和外界环境互动 |
| **电源** | 心脏 | 提供动力，心脏不给力，全身都动不了 |

几点关键理解：

- 内存负责"当下正在想的事"，硬盘负责"存放回忆"。没有立刻要用的事，就先存进硬盘这个"记忆深处"。
- 主板像神经，把大脑（CPU）的命令传给手脚（外设）。
- 电源像心脏，供电不稳定，整机就会断断续续、甚至无法工作。

所以：**人最重要的是大脑，计算机最重要的是 CPU 和内存**——CPU 要处理的数据来自内存；而过去的记忆就像硬盘，需要时再"想起来"（读取）。

## 十一、计算机硬件组成

回忆一下去电脑城买电脑的场景。面对琳琅满目的商品，电脑到底"贵在哪里"？答案是**配置**：

- 更强的 CPU
- 更大的内存
- 固态硬盘
- 更好的独立显卡
- 高分辨率显示器
- ……

### 计算机的三大组成部分

以普通家用主机为例，计算机由三部分组成：

1. **输入设备**：键盘、鼠标
2. **输出设备**：显示器（屏幕）
3. **主机部分**：机箱和机箱内部的各种零件

工作过程是：我们通过键盘、鼠标把数据输入主机 → 主机里的处理器进行计算 → 把图像或文字结果输出到屏幕上。

### 主机内部有什么

机箱里常见的零件包括：CPU、CPU 风扇、主板、内存、硬盘、显卡、电源，以及光驱等。

即使你没亲手组装过电脑也没关系——**笔记本和服务器内部其实也是这些东西，只是服务器的性能更强、用料更讲究而已。**

### 外设（输入 / 输出设备）

- **输入设备**：键盘、鼠标、触摸屏、摄像头、扫描仪、VR 体感设备等。
- **输出设备**：显示器、打印机、音箱、投影仪等。
- 主板上还集成/扩展了网卡、声卡、显卡等接口。

## 十二、计算机的用途分类

按照性能和用途，计算机大致可以分为四类：

| 类型 | 特点 | 典型用途 |
| --- | --- | --- |
| **超级计算机** | 运算速度最快，但制造、维护费用最高 | 国防军事、气象预测、太空科技、大规模仿真 |
| **大型计算机** | 通常有多个高速 CPU，能处理海量数据和复杂运算 | 大型企业核心主机、证券交易所、大型数据库 |
| **工作站** | 针对特殊用途设计，性能/价格比较高 | 学术研究、工程设计与分析 |
| **微型计算机** | 就是日常的个人电脑 | 笔记本、台式机，办公和家用 |

## 十三、容量单位与速度单位

### 容量单位

计算机底层只认识**二进制**，最小的单位叫做 **bit（位）**。但一个 bit 太小，于是用 **Byte（字节）** 作为基本计量单位：

```plain
1 Byte = 8 bit
```

随着存储容量越来越大，又出现了 KB、MB、GB、TB 等更大的单位（相邻单位之间是 1024 进制，详见第五篇）。

### 速度单位

- **CPU 的运算速度**常用 MHz、GHz 表示。Hz 的含义是"每秒多少次"，GHz 就是每秒十亿次。
- **网络传输速度**以 bit 为单位，常见单位是 **Mbps（Mbit per second，每秒多少 Mbit）**。

> ⚠️ 注意区分大 B 和小 b：**1 Byte = 8 bit**。所以运营商说的"100M 宽带"是 100 **Mbit**/s，理论上实际下载速度峰值约为 100 ÷ 8 ≈ 12.5 **MByte**/s。
>
> 同理，某 5G 测试速度 3000 Mbps，换算成下载速度约为 3000 ÷ 8 ≈ 375 MByte/s。

### 商家"坑"了你的硬盘吗？

你可能遇到过：买一块标注 **1TB** 的硬盘，格式化后系统里只显示约 **930GB**。这不是质量问题，而是**换算口径不同**：

- 操作系统按二进制算：**1 TB = 1024 GB**；
- 硬盘厂商按十进制宣传：**1 TB = 1000 GB**。

厂商说的"1TB"是 1,000,000,000,000 字节，除以系统的 1024×1024×1024，就只剩约 930GB 了。容量越大，这个"缩水"看起来越明显。

# 第三篇 · 核心硬件详解

## 十四、CPU（中央处理器）

服务器的 CPU 相当于人体的大脑，负责**运算和控制**，是决定服务器性能最核心的部件。主流品牌是 **Intel（英特尔）和 AMD**。

企业里常见的配置量级（了解即可）：

- 一般企业服务器：CPU 通常 2～4 颗，单颗多为多核；内存总量一般 16G～256G。
- 做虚拟化的宿主机（例如安装 VMware 的服务器）：CPU 通常 4～8 颗，内存 48G～128G，上面跑 6～10 个虚拟机。

### CPU 内部结构

无论手机还是电脑，最核心的部件都是**中央处理器（Central Processing Unit, CPU）**。CPU 芯片内部有一套"微指令集"，它的工作主要分为**运算**和**控制**两部分，对应两大单元：

- **算术逻辑单元（Arithmetic Logic Unit，简称 ALU）**：负责实现各种算术运算（加减乘除）和逻辑运算（与、或、非、比较等），又叫"运算器"。
- **控制单元（Control Unit，简称 CU）**：是整个 CPU 的指挥控制中心，负责程序流程管理，由指令寄存器、指令译码器、操作控制器等部件组成，协调整机有条不紊地工作。

更细一点，CPU 内部可以这样理解（即"CPU 基本组成结构"）：

- **运算器**部分：ALU、累加器、状态条件寄存器、缓冲寄存器；
- **控制器**部分：操作控制器 / 时序产生器、指令译码器、指令寄存器、程序计数器、地址寄存器；
- 它们通过**数据总线（DBUS）**和**地址总线（ABUS）**与外部交换数据。

### 数据是怎么流动的

CPU 处理的数据全部来自内存，而内存里的数据来自键盘等输入设备或硬盘；处理完的结果也要先写回内存，最后才送到输出设备。整体流向：

```text
键盘/鼠标                显示器
 (输入)                  (输出)
    │                      ▲
    ▼                      │
   内存 ◄────► CPU（控制单元 + ALU）
    ▲   数据总线
    │
   硬盘（外置存储）
```

**所有数据都要经过内存中转，进出由 CPU 发出控制命令。** 无论是打开应用还是读取文件，都要先加载到内存里，CPU 才能处理。这就是为什么"内存足够大，电脑运行才流畅"。

### CPU 的两大架构：RISC 与 CISC

所有软件都要先读入内存，再由 CPU 内部的微指令来调度执行。世界上主流的 CPU 架构分为两种：

#### 精简指令集 RISC（Reduced Instruction Set Computer）

- 指令设计精简，每条指令执行时间短、完成的动作单纯。
- 代表产品：Oracle（甲骨文）的 SPARC 系列、IBM 的 Power Architecture 系列，以及应用极广的 **ARM 架构**。
- **ARM 是当下最典型的 RISC**：全球绝大多数手机、平板、嵌入式设备都用 ARM 架构，苹果、高通、三星、华为等的移动芯片都是在 ARM 基础上发展起来的。

> 💡 现在很多服务器、笔记本也开始采用 ARM 架构 CPU（如苹果 M 系列、AWS Graviton、华为鲲鹏、NVIDIA Thor 等车载计算平台），靠低功耗和多核并发取胜。

#### 复杂指令集 CISC（Complex Instruction Set Computer）

- 每条指令可以执行较复杂的底层硬件操作，指令数量多且复杂。
- 代表产品：大家熟悉的 **Intel、AMD 的 x86 架构** CPU，大量用于个人电脑和传统服务器。

#### 32 位与 64 位

你一定听过"32 位、64 位"的说法。这里的"位"指 **CPU 一次能处理的数据宽度**：

- 64 位 CPU 一次能读写 64 bit 数据；32 位 CPU 一次只能读写 32 bit。
- 由于这个宽度限制，**32 位 CPU 最多只能有效使用约 4GB 内存**，所以现在的电脑和服务器基本都是 64 位（x86_64 / amd64）。

不同 x86 CPU 还会通过新增指令集来增强能力，比如 4K 视频编解码加速、虚拟化加速（Intel VT-x / AMD-V）、降低功耗等。

### 主板芯片组：北桥与南桥

主板是连接各部件的核心载体，主板上负责"沟通"各部件的芯片组，很大程度决定了整机性能。早期芯片组通常分为两个"桥"：

- **北桥**：连接速度快的部件——CPU、内存、显卡；
- **南桥**：连接速度慢的部件——硬盘、USB、网卡等。

> 💡 现代 CPU 已经把北桥的功能（内存控制器、甚至显卡）整合进了 CPU 内部，所以现在新主板上往往只剩下一颗"平台控制器"（PCH / SoC），不再有传统的南北桥。但这两个概念仍然经常被提到。

由于 CPU 运算量大、发热高，必须配风扇主动散热。不同 CPU 型号的插槽（针脚）不同，能搭配的主板也不同，升级时一定要确认插槽是否兼容。整体上，Intel 以稳定见长、办公和服务器用得多；AMD 在多核和游戏方面表现强劲。

### CPU 的三种封装类型

| 封装 | 全称 | 特点 |
| --- | --- | --- |
| **PGA** | Pin Grid Array，插针网格阵列 | 针脚在 **CPU** 上，主板上是一排排小孔 |
| **LGA** | Land Grid Array，平面网格阵列 | 取消针脚、只留触点，针脚做在**主板**上（现在 Intel 桌面 CPU 主流） |
| **BGA** | Ball Grid Array，球栅网格阵列 | 用焊锡球直接**焊接**在主板上，不可随意更换（手机、轻薄本、嵌入式常用） |

## 十五、内存

内存（Memory）是计算机中非常重要的部件，它解决了一个关键矛盾：**CPU 极快，而硬盘相对很慢，两者速度严重不对等。** 内存就是 CPU 和硬盘之间数据交互的"桥梁"。

### 内存的工作方式

默认情况下：

- CPU 从内存读写数据；
- 内存从硬盘读写数据。

为了提高效率，开机或运行软件时，会把常用数据先从硬盘读入内存备用，这样 CPU 要用时就能立刻拿到，整机速度明显变快。

### 内存的特点

- 内存是**临时存储器**，只负责数据中转，**不能永久保存**。
- 它是 CPU 唯一能直接访问的存储器：CPU 从内存读取指令和数据，再把结果送回内存。
- 程序运行时会被加载到内存；服务器关机或程序关闭后，这部分数据就从内存中释放。
- 内存的容量和速度，直接决定了数据传输快慢。
- **内存和 CPU、硬盘并称电脑"三大件"。**

### 内存的种类

我们平时说的内存主要是**动态随机存取存储器（Dynamic Random Access Memory，DRAM）**，它最大的特点是：**必须通电才能保存数据，一旦断电数据就丢失。**

DRAM 经历了几代发展：DDR → DDR2 → DDR3 → DDR4（现在已有更新的 DDR5），每一代速度更快、电压更低。不同代的内存条插槽互不兼容。内存条还分台式机和笔记本两种规格，长度和外形不同。

### 多通道设计

"电脑卡？加内存！"——因为数据都要先进内存，所以内存容量越大，电脑往往越流畅。

如果插两条（或多条）内存，最好选择**相同品牌、相同频率、相同型号**。芯片组会把它们组合起来并行工作：单条是 64 位带宽，两条就能凑成 128 位，这就是**双通道**。双通道下两条内存**同步读写**，能提升整体性能（同理还有四通道）。

### 程序、进程、守护进程

这三个概念和内存密切相关：

- **程序（Program）**：用 Python / Go 等语言写好、静静躺在硬盘上的代码文件，是**静态**的。
- **进程（Process）**：程序被运行起来后，数据被加载进内存，是**正在执行**的程序。
- **守护进程（Daemon）**：一种在**后台持续运行**、通常随系统启动、不依附于某个终端的进程，名字常以字母 d 结尾（如 httpd、sshd、crond），d 就是 daemon 的意思。

一个通俗的比喻：

| 概念 | 比喻 |
| --- | --- |
| 程序 | 电脑里存着的一部影片 |
| 进程 | 双击把影片打开了 |
| 守护进程 | 一直在后台持续播放、提供服务 |
| 关闭程序 | 内存中的数据被释放 |

### 用内存提升用户体验

**门户 / 大网站的极端案例（高并发写入，如抢红包、微博热搜）：**

面对高并发、大量"写"数据，系统会**先把数据写到内存**，积累到一定量后，再定时或批量写入磁盘。这样能减轻磁盘压力（减少磁盘 IO，IO 即 Input/Output，磁盘的读写操作）；而对外提供访问时，数据也还是从内存读取。

- **优点**：写内存速度极快，能扛住微博、微信、秒杀这类瞬时高并发。
- **缺点**：万一断电，内存里还没来得及写入磁盘的数据可能丢失。

常见的"防止数据丢失"手段：

1. 服务器主板上配备备用电池，断电瞬间把内存数据回写到磁盘；
2. 配备 **UPS 不间断电源**，争取几分钟到一小时的缓冲时间；
3. 选择双路供电机房，服务器用双电源分别接不同线路，并分散到不同机柜、不同可用区。

**中小企业案例：**

对于并发没那么大、数据量也一般的网站（典型的"读多写少"业务），会**先把数据写入磁盘，再由程序把磁盘数据加载到内存**，之后对外通过读内存来提供服务。

这两种方案的核心思想完全一致：**利用内存速度远快于磁盘的特性，把数据尽量放到内存中读写。**

## 十六、显卡

显卡（Graphics Card）是计算机中负责图像输出的设备，它的主要职责：

- 把系统需要显示的信息转换、驱动给显示器，提供扫描信号，控制画面正确显示；
- 是连接显示器和主板的重要组件；
- 是"人机对话"的重要设备之一。

图像显示会占用存储空间，所以显卡自带一块专用内存，叫做**显存**。**显存容量和速度会影响屏幕分辨率、色彩深度以及游戏流畅度。**

早期的 3D 运算也由 CPU 完成，但 CPU 任务太多，难以兼顾大量图形计算，于是显卡厂商在显卡中嵌入了专门的图形处理芯片——**GPU（Graphics Processing Unit）**。大型 3D 游戏、图形渲染对 GPU 的并行计算能力和数据传输速度要求都很高。

> 💡 GPU 最初为图形设计，但它有成千上万个小核心、特别擅长并行计算，所以后来被广泛用于**深度学习、科学计算**。运维排查时也常通过 `nvidia-smi` 查看 GPU 状态。

### 显卡、GPU 与"挖矿"

简单说，"挖矿"就是：**利用芯片做大量与随机数相关的计算，谁先算出符合要求的答案，谁就能获得一枚虚拟币作为奖励**；虚拟币再通过一定途径兑换成现实货币。

- 算力越强的芯片，越容易更快找到答案，单位时间收益越高。
- 因为带有随机碰运气的成分，可能一块芯片下一秒就找到答案，也可能十块芯片算一周都没结果。
- 于是出现了内置大量芯片的**矿机**；多台矿机组成**矿场**；而**矿池**是把众多"个体户"组织起来一起算，无论谁找到答案，都按各自贡献的算力比例分配收益，让收入更稳定。

打个通俗的比方：

- 我在纸上写一串数字、给出部分提示，谁猜对就给谁奖金 → **挖矿**
- 越聪明的人能做出越多猜测 → **算力**
- 有人出钱请很多人一起猜 → **矿场**
- 有人召集大家一起猜、按每个人的猜测次数分奖金 → **矿池**

正因为 GPU 比 CPU 更擅长这种并行计算，所以早期挖矿芯片从 CPU 升级到了 GPU，算力更强、更容易出币。

### 显卡接口

如果不是为了游戏或计算，而只是作为网络服务器，那么入门级、甚至主板自带的简单显卡就够用了——因为服务器很少做图像处理，而且**绝大多数 Linux 服务器根本不装图形界面**。

显卡与显示器 / 主机的常见视频接口：

| 接口 | 特点 |
| --- | --- |
| **VGA** | 传输模拟信号，15 针，比较老，体积较大 |
| **DVI** | 数字信号，常用于早期液晶显示器 |
| **HDMI** | 当前主流，可**同时传输图像和声音**，电视、台式机广泛使用 |
| **DisplayPort（DP）** | 高性能数字接口，也能同时传图像和声音，常见于高刷新率显示器 |

## 十七、磁盘

我们的工作、学习、娱乐都离不开计算机存储的大量资料：学籍档案、工业数据、照片视频、学习资料……这些数据需要被长期记录、反复读取。常见的存储介质有：机械硬盘、固态硬盘、U 盘、光盘等。

> 由于 CPU、输入输出设备和存储器之间要大量交换数据，**存储器的速度和容量也是影响整机性能的主要因素之一**。尤其在服务器优化场景，**硬盘性能往往是决定网站性能的关键环节**。

磁盘是**永久存放数据**的存储器（磁盘上一般也带少量缓存芯片）。常规机械硬盘的读写速度比内存慢很多，所以企业里才会把大量数据缓存到内存——这是互联网解决访问速度慢的必备方案。

目前常用硬盘分两种：

- **固态硬盘（SSD）**：速度快，但单位容量价格高；
- **机械硬盘（HDD）**：速度相对慢，但容量大、价格便宜。

### 磁盘接口与性能梯队

磁盘接口经历了 IDE、SCSI、SATA、SAS 等几代。目前：

- IDE 已被 **SATA** 取代，SCSI 已被 **SAS** 取代；
- 性能与价格排序：**SSD ＞ SAS ＞ SATA**。

### 机械硬盘的内部结构与读写原理

机械硬盘内部主要由**圆形盘片、磁头臂、磁头、主轴马达**组成。数据以磁信号的形式记录在盘片上，读写过程是：

1. 主轴马达带动盘片高速旋转；
2. 磁头臂移动，把磁头送到目标位置上方；
3. 磁头在盘片表面进行数据的读取或写入。

### 盘片数据三要素：扇区、磁道、柱面

理解硬盘存储，有三个核心概念：

| 概念 | 英文 | 说明 |
| --- | --- | --- |
| **扇区** | Sector | 盘片上被切分出的最小存取区块，传统大小为 **512 字节**（现代新盘常见 4KB） |
| **磁道** | Track | 盘片上同一个同心圆上的所有扇区，组成一圈磁道 |
| **柱面** | Cylinder | 硬盘里有多张盘片，**所有盘片上同一位置（同半径）的磁道**叠在一起，就形成一个柱面 |

想象一下盘片的样子：从最外圈开始有一个个同心圆环（磁道），每个圆环又被径向切成很多小段（扇区）。由于外圈圆周更长、能放下更多扇区，为充分利用空间，**数据一般从外圈往内圈写入**（外圈通常也更快）。

### 磁盘分区与 MBR

硬盘在使用前通常要分区。以传统的 **MBR 分区**方式为例，硬盘的**第一个扇区（0 磁头 / 0 磁道 / 1 扇区，共 512 字节）**非常关键，它记录了开机引导和分区信息，分为三部分：

```text
┌──────────────────────────────────────────────────┐
│  主引导记录 MBR   │   磁盘分区表 DPT   │ 结束标识  │
│     446 字节      │      64 字节       │  2 字节  │
│   (引导程序)       │ 4 个表项 × 16 字节 │  55AA   │
└──────────────────────────────────────────────────┘
```

- **446 字节：MBR（主引导记录）**，存放开机引导程序；
- **64 字节：DPT（磁盘分区表）**，最多记录 4 个分区表项；
- **2 字节：结束标志 55AA**，用来标识这是一块有效的引导扇区。

因为分区表只有 4 个表项，所以一块 MBR 硬盘最多分 4 个**主分区**。如果需要更多分区，就要拿出一个主分区作为**扩展分区**，再在扩展分区内部划分若干**逻辑分区**。在 Linux 中设备名形如：

- 主分区：`/dev/sda1`、`/dev/sda2`、`/dev/sda3`
- 逻辑分区：从 `/dev/sda5` 开始编号（1～4 预留给主分区）

> 💡 MBR 是较老的方案，单盘容量上限约 2TB、最多 4 个主分区。现在大容量硬盘普遍使用 **GPT 分区**（配合 UEFI），几乎没有这些限制。这些在后面磁盘管理章节会实操。

### 主流接口详解

#### SATA

SATA（Serial ATA，串行 ATA）是一种总线标准，主要用于主板和硬盘、光驱之间的数据传输，是机械硬盘和普通 SSD 上最常见的接口。SATA 分三代：

| 版本 | 理论速度 (MB/s) |
| --- | --- |
| SATA 1.0 | 150 |
| SATA 2.0 | 300 |
| SATA 3.0 | 600 |

受机械硬盘物理结构限制，普通机械盘实际持续读写速度一般在 150～200 MB/s 左右。

#### SAS

SAS（Serial Attached SCSI，串行连接 SCSI）是新一代 SCSI 技术，和 SATA 一样采用串行技术以获得更高速度，并通过缩短连线改善机箱内部空间。它是在并行 SCSI 之后开发的全新接口，设计目标是**提升存储系统的性能、可用性和扩展性**，同时兼容 SATA 硬盘。

SAS 能为主流服务器和企业级存储提供高带宽、高扩展性和高可靠性，很好地满足了网购、银行交易这类**频繁、即时、随机存取**场景。SAS 盘比 SATA 盘贵，企业数据中心和磁盘阵列卡仍大量使用 SAS。

#### USB

USB（通用串行总线）是连接计算机与外部设备的总线标准，广泛用于个人电脑、移动设备、摄影器材、数字电视等领域。外置硬盘、U 盘就是通过 USB 和主机连接。各版本理论速度：

| 版本 | 理论速度 (MB/s) |
| --- | --- |
| USB 1.0 | 1.5 |
| USB 2.0 | 60 |
| USB 3.0 | 500 |
| USB 3.1 | 1000 |

以上是理论值，受实际设备和线材限制，USB 3.0 的实际读写速度通常在 100 MB/s 上下。USB 3.1 速率可达 10Gbit/s，新型 Type-C 接口支持正反盲插、供电能力更强。

### 固态硬盘（SSD）

机械硬盘启动时要先让马达带动盘片旋转，再移动磁头找到目标扇区，**寻道延迟高**，工作时还有震动和噪音。于是厂商用闪存芯片做成大容量存储设备，接口沿用 SATA、SAS 或更快的 PCIe，内部没有磁头和盘片，这就是**固态硬盘（Solid State Drive，SSD）**。

对比：

- **HDD**：有机械转动，抗震性和性能较弱，工作时有"吱"的读写声，待机旋转也有一定功耗。
- **SSD**：无机械结构，抗震强、性能好、功耗低、工作时完全安静，通过闪存直接读写，几乎没有寻道延迟。

> ⚠️ SSD 的闪存颗粒有**写入擦除次数（寿命）限制**，但正常使用通常能覆盖设备更新周期；企业里还会用 RAID、掉电保护等机制进一步保障。
>
> 💡 走 **PCIe / NVMe** 协议的 SSD 比 SATA SSD 快数倍，是现在高性能服务器和新电脑的主流。

### 磁盘碎片与 IOPS

Windows 上有一个"磁盘碎片整理"功能。它存在的原因是：硬盘使用一段时间后，由于反复写入、删除文件，空闲扇区会分散到不同物理位置，导致一个文件被拆得东一块西一块。读取这种"碎片"文件时，磁头要来回移动很久，明显降低访问速度。碎片整理就是尽量把同一文件挪到连续的扇区上。

衡量磁盘性能时，除了连续读写速度，还有一个关键指标：**IOPS（Input/Output Operations Per Second，每秒读写操作次数）**。**IOPS 越大，代表磁盘每秒能处理的零散请求越多、性能越强。** SSD 的 IOPS 通常是机械硬盘的成百上千倍，这也是它在高并发场景碾压机械盘的原因。

### RAID 与 RAID 卡

**RAID（Redundant Arrays of Independent Drives，磁盘冗余阵列）**：把多块独立的物理硬盘按一定方式组合成一个（或一组）逻辑硬盘，从而获得比单盘更高的容量、性能或数据冗余。

- 数据被切分成区段，分散存放在各块硬盘上，靠并行读写提升性能；
- 还可以利用**校验（Parity）**信息，在其中一块硬盘损坏时仍能读出数据，更换新盘后再把数据重建出来。

可以打个比方：你有很多块土地，单独管理既麻烦效率又低，把它们整合成一大块统一规划，才能发挥最大效益。服务器一般会专门配一块 **RAID 卡**（带处理芯片和缓存）来管理这些硬盘。

### RAID 常见级别对比

最常用的级别是 **RAID 0 / 1 / 5 / 10**：

| 级别 | 通俗叫法 | 最少硬盘 | 冗余（能坏几块） | 可用容量 | 性能 | 典型场景 |
| --- | --- | --- | --- | --- | --- | --- |
| **RAID 0** | 条带 | 1 | 无冗余，坏一块全完 | 所有盘容量之和 | **读写最快** | 只追求速度、数据可丢：数据库 / 存储从库 |
| **RAID 1** | 镜像 | 2 | 100% 镜像，可坏一块 | 总容量的一半（即 1 块盘） | 写入一般、读取快 | 只追求安全：系统盘、监控服务器 |
| **RAID 5** | 带校验条带 | 3 | 最多坏一块 | 损失 1 块盘容量 | 读取快、写入一般 | 数据库、通用存储（兼顾容量与安全） |
| **RAID 10** | 镜像 + 条带 | 4 | 可坏一半（按组合） | 总容量的一半 | **读写都很快** | 高并发 / 高访问量：数据库主库、核心存储 |

几个排序方便记忆：

- 冗余从好到坏：RAID 1 / RAID 10 ＞ RAID 5 ＞ RAID 0
- 性能从好到坏：RAID 0 / RAID 10 ＞ RAID 5 ＞ RAID 1
- 成本从低到高：RAID 0 ＜ RAID 5 ＜ RAID 1 ＜ RAID 10

企业里的常见选择：

- 单台、很重要、盘不多的**系统盘**：RAID 1；
- **数据库 / 存储主库**：RAID 10（从库可考虑 RAID 5 / RAID 0）；
- 数据不多的 **Web 服务器**：RAID 5 或单盘；
- 多台监控 / 应用服务器：RAID 0 / RAID 5。

## 十八、主板与 BIOS

### 主板

主板是计算机中最重要的"平台"部件，也是机内最大的集成电路板，它**直接或间接把所有设备连接在一起**。主板的好坏直接影响整机速度和稳定性，同时它提供大量插槽和接口，为后续扩展硬件提供可能。

主板上一般有：BIOS 芯片、I/O 控制芯片、各类插槽（CPU、内存、PCIe）、SATA / USB 接口、面板开关与指示灯接口、电源供电接口等。现在主板大多直接集成了网卡、声卡，很多还集成了显卡（核显输出）。

### BIOS 与 CMOS

很多玩家喜欢"超频"：在主板 **BIOS** 里把 CPU 的频率手动调高来提升性能，但频率超出稳定范围可能导致死机、蓝屏。

- 这类设置会被保存在主板上的一块 **CMOS** 芯片里，它需要靠额外供电才能在关机后继续保存信息——这就是主板上那颗**纽扣电池**的作用。电池没电后，BIOS 设置会恢复默认、系统时间也会复位。
- **BIOS（Basic Input Output System，基本输入输出系统）**是写在主板一颗芯片里的固件程序。这颗芯片在断电下也能保存数据，属于 **ROM（只读存储器）**，现在多用可刷写的 Flash 芯片。
- 开机时按 **Del / F2 / F12 / F11**（因品牌而异）即可进入 BIOS 设置界面。

BIOS 掌握着硬件配置信息和开机启动顺序等，对系统非常重要。

> 💡 实用提示：装系统选择 U 盘启动、或学习虚拟化时需要开启 CPU 的 **VT（虚拟化）**支持，都是在 BIOS 里设置。现在新机器正逐步用 **UEFI** 取代传统 BIOS，配合 GPT 分区。

## 十九、电源与 UPS

### 机箱

机箱用来容纳和固定硬件，起到防尘、防磕碰、防静电以及屏蔽电磁辐射的作用。挑选机箱主要关注：散热是否良好、板材结不结实易不易变形、空间和硬盘位能不能满足以后扩展、走线是否方便。

### 电源供应器（Power）

机箱内那个体积较大、引出很多电源线的部件就是电源。CPU、内存、主板、硬盘等所有硬件都要靠它供电。随着硬件性能提升，**劣质或功率不足的电源可能导致供电不稳、重启甚至硬盘、内存数据损坏**，所以电源不能只图便宜。

- 服务器电源和 PC 电源一样属于开关电源，标准上常见 ATX 和服务器专用的 SSI 等。
- 电源相当于人体的**心脏**，一定要选质量可靠、功率有余量的产品。
- **生产环境中，承载核心业务的单台服务器一般使用双电源、分别接 A / B 两路供电。**
- 如果是集群（多台机器一起做同一件事、彼此有冗余），单台也可以不强制双电源。

### UPS 不间断电源

**UPS（Uninterruptible Power Supply，不间断电源）**：把蓄电池（多为铅酸免维护电池）和主机相连，通过逆变器等电路，在断电时把电池的直流电转换成交流电继续给设备供电。

- **市电正常时**：UPS 对市电稳压后供给负载，同时给内部电池充电；
- **市电中断时**：UPS 立刻用电池经逆变器继续输出 220V 交流电，让设备不掉电、不损坏，并留出正常关机时间；
- UPS 对电压过高或过低通常也能提供保护。

它的意义就是防止"突然断电"导致的：数据没来得及保存、文件损坏、设备异常停机。在线式 UPS 的切换时间可以做到 0 秒、输出纯正弦波，是服务器机房的标配之一。

## 二十、网卡

### 有线网卡

网卡（又称网络适配器，**NIC**，Network Interface Card）是计算机接入网络的必备设备：

- 计算机没有网卡，就无法和其他计算机通信，也得不到网络服务；服务器没有网卡，就根本称不上服务器。
- 普通 PC 的网卡主要把电脑接入局域网（LAN）；服务器网卡一般用于服务器与交换机等网络设备之间的连接。
- 服务器通常配备多块、多个网口，支持更高的速率（千兆、万兆甚至更高速）和冗余。

### 无线网卡

无线网卡的作用和普通网卡一样，都是连接网络，区别只是不通过网线、改用无线信号收发。它必须在已有的无线网络（热点 / 路由器）覆盖范围内才能使用。常见形态有：USB 无线网卡、台式机 PCIe 无线网卡、笔记本内置的无线网卡。

### 常见网卡 / 网络故障排查思路

当连不上网时，可以按从简单到复杂的顺序检查（均为只读排查）：

1. **物理连接**：网线是否插好、网卡是否被识别，接口指示灯是否正常；
2. **驱动 / 系统识别**：系统能否看到网卡，USB 网卡要确认端口和驱动正常；
3. **无线信号与供电**：是否在无线信号覆盖范围内、信号是否太弱，AP / 路由器是否正常工作；
4. **网络配置**：是否拿到了正确的 IP 地址、网关和 DNS 配置是否正确。

# 第四篇 · 服务器基本知识

## 二十一、什么是服务器

服务器其实也就是一台计算机，同样由 CPU、主板、内存、硬盘、网卡等组成。不同的是，服务器被定义为**高性能、高可靠的计算机**，作为网络中的节点处理通信中的数据和信息，是网络时代的基础。

服务器是**管理资源、并为用户提供服务**的计算机。按提供的服务，常见的有文件服务器、数据库服务器、应用服务器等。相比普通 PC，服务器在以下方面要求高得多：

- **稳定性**：要支持 7×24 小时不间断运行，甚至多年不关机；
- **性能**：能承受大量用户同时并发访问；
- **安全性、可扩展性、可管理性**。

所以服务器的硬件更强：可以装多颗 CPU、更多内存、更多硬盘，主板和机箱也更大，普遍采用冗余电源、高速网卡，并支持硬盘热插拔。

服务器对显示的要求很低，一般不接显示器、靠**远程管理**来运维，所以通常只用集成显卡，不需要独立显卡。真实的物理服务器一般都放在**机房**里托管、闲人免进（例如部分苹果服务的数据就托管在"云上贵州"的机房）。

## 二十二、服务器分类、尺寸与品牌

### 按规模 / 用途分类

**按规模分：**

- 大型服务器：数据中心、企业核心业务
- 中型服务器：公司部门级业务
- 小型服务器：入门级、个人 / 小型云服务器

**按用途分：**

- Web 服务器、数据库服务器、文件服务器、邮件服务器、视频点播服务器等。

### 按外形分类

#### 机架式服务器

- 外形不像普通电脑，更像一个个"抽屉"，有 1U、2U、4U 等规格；
- 统一安装在标准 19 英寸机柜里，密度高、便于集中管理，是数据中心最常见的形态，多为功能型服务器。

#### 刀片式服务器

- 在一个标准机架式机箱（刀片机框）内插入多块卡式服务器单元（"刀片"），实现高可用、高密度；
- 形象地说，就像箱子里整齐排列的一摞书。

每块"刀片"本质上就是一块系统主板，可以通过本地硬盘独立启动自己的操作系统（Windows / Linux 等），像一台台独立服务器，分别服务不同用户。单块刀片性能有限，但可以通过系统软件把它们组成**集群**：高速网络互联、共享资源、共同服务；插入新刀片即可横向扩展。刀片支持**热插拔**，更换方便、维护时间短。

#### 塔式服务器

- 外形、结构和立式 PC 最接近，最容易理解；
- 因为主板扩展性强、插槽多，机箱通常比普通 ATX 机箱更大，内部预留充足空间用于硬盘和电源冗余；
- 缺点是体积大、占地方，需要多台协同工作时不如机架式好管理。

### 服务器尺寸（U）

服务器在机柜里按**高度**计量，单位是 **U（Unit）**：

```plain
1U = 1.75 英寸 ≈ 4.445 厘米
```

常见规格有 1U、2U、4U。1U 最省空间但扩展性受限；2U/4U 能装更多硬盘、散热更好。

### 常见品牌

- **DELL 戴尔**：市场占有率高，大多数公司都在用；
- **HP（HPE）慧与**；
- **IBM**：传统强项在银行、政府、大型企业，价格贵（其 x86 服务器业务后来已出售）；
- **浪潮（Inspur）**、**联想（Lenovo）**等国产厂商。

### 品牌型号小知识

**DELL PowerEdge** 常见型号（按年代）：

| 年代 | 1U | 2U |
| --- | --- | --- |
| 2010 年前 | 1850 / 1950 | 2850 / 2950 |
| 2010–2013 | R410 / R610 | R710 |
| 2014–2016 | R420/R430、R620/R630 | R720 / R730 |

Dell PowerEdge 服务器官网（可查看在售型号与参数）：

```plain
https://www.dell.com/zh-cn/work/shop/category/servers
```

例如经典的 **PowerEdge R720**（2U，至强 E5 处理器、支持双路 CPU、大容量内存和多块 SAS/SATA 硬盘、冗余电源、多个千兆网口、带 RAID 卡），就是一代非常常见的机型。

**IBM** 常见命名（按高度）：

- 1U：x3550（M3 / M5 等）
- 2U：x3650

```plain
（IBM 小型机、Oracle 数据库、EMC 存储设备）
```

## 二十三、机房托管与云服务器

### 为什么要把服务器放进专业机房

放在普通办公室 / 企业小机房会有不少问题：

1. 无法保证一年 365 天 7×24 小时稳定、充足的供电；
2. 物理和网络安全防护不足；
3. 接入的往往是经过分流的民用带宽，速度和质量没保障；
4. 需要高薪长期雇佣专门工程师维护；
5. 温度、湿度、防尘等环境不达标，会缩短服务器寿命、增加故障率，甚至造成数据损失。

而专业 **IDC 数据中心**正是为了让服务器"更好、更稳、更快、更安全"运行而建设的，提供：恒温恒湿、冗余供电、高速骨干带宽、安防消防和专业运维。

选择机房时通常优先考虑：

1. 正规电信 / 联通或多线 BGP 机房，稳定性更有保障；
2. 位于骨干网（ChinaNet 等）节点上的机房，访问速度快；
3. 技术能力和口碑好的机房，服务和安全更可靠。

### 云服务器

所谓"云"，就是网络、互联网的意思。**云服务器（云主机）是一种简单高效、安全可靠、算力可弹性伸缩的计算服务。** 相比传统物理服务器，它有几个明显优势：

1. **升级方便**：配置不够用时，可以在不重装系统、不影响业务的情况下弹性调整 CPU、内存、硬盘。
2. **访问速度快**：带宽通常是多线 / BGP 接入，网络可自动选择质量更好的线路。
3. **存储省心**：支持数据多副本、自动备份，硬件故障时数据不易丢失，日常维护由云厂商负责。
4. **安全稳定**：底层是集群化架构，支持故障节点快速迁移 / 重建，计算节点损坏也能很快恢复、不影响数据。
5. **性价比高**：按需付费、用多少算多少，不会像自建机房那样一次性投入大量成本、还容易资源闲置。

> 💡 云的本质可以理解为：云厂商把海量的 CPU、内存、硬盘、网络组成一个巨大的"资源池"，再按需切分给不同用户——有人要 8 核 200G，有人要 2 核 20G，互不影响。
>
> 当然，使用云也要选择可靠的知名厂商，并做好自己的备份和安全配置。

## 二十四、远程管理卡与机房布线

### 远程管理卡

远程管理卡是服务器上的一块硬件，提供独立的以太网口，接入管理网络后即可远程访问，**即使主机操作系统宕机、甚至没开机，也能远程控制**。

- 有服务器**主板自带**的基础远程管理：一般能远程开机、关机，但可能看不到开机画面过程；
- 也有**独立 / 授权版**的完整远程管理卡，能看到远程屏幕、装系统、看硬件状态，相当于把键盘、鼠标、显示器搬到了网上；
- 有了它，服务器出问题时不用人跑到机房，能快速定位和恢复。

常见品牌的远程管理功能如 Dell 的 **iDRAC**、HP 的 **iLO**、浪潮的 **IPMI/BMC** 等。大客户通常用这类带外（带外管理网）远程管理；超大规模客户还会派驻人员驻守机房。

### 机房布线

机房里网线、光纤、电源线的走线非常讲究。专业布线会使用理线架、走线槽，把线缆捆扎整齐、贴好标签、强弱电分离；非专业的乱拉乱接则像一团"面条"，不仅难看，还会导致散热变差、故障难以排查，"网速不稳定、老掉线"很多时候和劣质布线、接触不良有关。整齐规范的布线是机房可维护性的基础。

# 第五篇 · 软件基本知识

## 二十五、二进制与数据单位

### 计算机为什么用二进制

计算机通过电位（电路的通 / 断）来记录信息，因此底层只能识别 **0 和 1** 两个数字，计算机内部的数据都以**二进制**形式存储和运算。

二进制由德国数学家、哲学家**莱布尼茨**于 1679 年提出（他还曾从中国《易经》的阴阳八卦中获得灵感）。它的特点是：

- 只用 0、1 两个数码，**基数为 2**；
- 进位规则"**逢二进一**"，借位规则"**借一当二**"；
- 可以把它想象成一个极小的开关：**开 = 1，关 = 0**。现代计算机中的数据主要以**补码**形式存储。

### 位、字节与换算关系

- **位（bit，比特）**：计算机存储数据的**最小单位**，一个二进制位只能表示 0 或 1。要表达更多信息，就要把多个位组合起来，通常以 8 位为一组。
- **字节（Byte，简记 B）**：计算机数据处理的**基本单位**，规定 **1 Byte = 8 bit**。

完整的换算关系：

```plain
1 Byte = 8 bit，1 KB = 1024 B，1 MB = 1024 KB，1 GB = 1024 MB
1 TB = 1024 GB，1 PB = 1024 TB，1 EB = 1024 PB，1 ZB = 1024 EB
```

> 💡 在 ZB 之后还有 YB（Yottabyte，1 YB = 1024 ZB）。GB、TB 是我们日常最常接触的量级，PB、EB 则常用来描述大型数据中心的数据规模。
>
> ⚠️ 注意上面是操作系统 / 内存使用的 **1024（2 的 10 次方）**口径；硬盘厂商标容量时多用 1000 口径，这就是前面说的"硬盘缩水"原因。

### 十进制与二进制的换算

- **十进制**"逢十进一"：个位满十归零、十位加一；
- **二进制**"逢二进一"。

一个十进制数，本质是每一位乘以 10 的若干次方之和：

```plain
3456 = 3*10**3 + 4*10**2 + 5*10**1 + 6*10**0
```

二进制同理，只是把底数 10 换成 2。例如二进制 `100100` 换算成十进制：

```plain
100100 = 1*2**5 + 0*2**4 + 0*2**3 + 1*2**2 + 0*2**1 + 0*2**0 = 36
```

十进制转二进制常用"**除 2 取余、逆序排列**"。例如把十进制 88 反复除以 2、记录每次余数，最后倒过来读：

```plain
十进制数 88 转换为二进制为 1011000
```

如果想快速验证或换算，可以使用在线进制转换工具：<https://tool.lu/hexconvert/>

## 二十六、字符编码

光有数字还不够，计算机还要表示文字。"字符编码"就是一套**把字符（汉字、字母、符号）和数字（二进制）相互对应**的规则。常见的编码有 ASCII、GBK、Unicode / UTF-8 等。

历史上不同国家各自搞编码，很容易出现"乱码"；现在业界普遍用 **UTF-8**（Unicode 的一种实现）来统一表示世界上各种文字。可以阅读这篇文章了解来龙去脉：

<https://www.cnblogs.com/alex3714/articles/5465198.html>

> 💡 运维经验：日志、终端出现乱码，十有八九是"编码不一致"（比如文件是 UTF-8、却按 GBK 解释）。排查中文乱码时，先确认文件和终端用的是哪种编码。

## 二十七、程序的编译与解释

计算机通电后只是一堆硬件，想让它有"灵魂"，还得安装软件和操作系统。而 CPU 只认自己的**微指令**（机器语言，即 0 和 1）。想让计算机干活，理论上就得直接发送它能听懂的机器指令。

### 直接写机器语言的问题

- 全是 0/1，人根本没法写、没法读；
- 必须了解所有硬件细节、操控硬件指令；
- **不可移植**：每种 CPU 的指令集不同，给这种 CPU 写的程序，换台机器就跑不了；
- 不通用：针对某一种用途写的程序，换个用途又得重写。

### 编译器：把人话翻译成机器话

直接写机器语言太痛苦，于是科学家设计出人类能看懂的**高级编程语言**，再通过**编译器 / 解释器**把它"翻译"成机器能执行的指令。这样学习和编写程序就容易多了。

"编译"和"解释"都有"翻译"的意思，区别在于**翻译的时机**：

| | 编译型 | 解释型 |
| --- | --- | --- |
| 翻译方式 | 执行前**一次性**把整个程序翻译成机器码，生成可执行文件 | **边执行边翻译**，由解释器逐句读取执行 |
| 代表语言 | C、C++、Go | Python、Shell、JavaScript |
| 特点 | 运行速度快，但和特定平台绑定 | 跨平台灵活、便于修改，但通常速度慢一些 |

打个比方，就像读一本外文书：

- **编译**：请翻译先花时间把整本书从头翻译好，再把母语版整本交给你读（之后反复读都很顺、很快）；
- **解释**：请翻译坐在旁边，你看一句他给你翻一句；想往回看，还得重新翻。

> 💡 介于两者之间还有"先编译成字节码、再由虚拟机解释/JIT 执行"的方式，典型如 Java、Python。理解"翻译时机"这个核心区别即可，不必纠结分类。

## 二十八、操作系统与系统调用

### 操作系统是什么

**操作系统（Operating System，OS）本质上也是一组程序**，这组程序的重点是：**管理计算机的所有活动、驱动系统中的全部硬件。**

它的核心职责包括：

- 让 CPU 能进行逻辑判断和运算；
- 让内存能载入 / 读出数据和程序；
- 让硬盘能被读写、网卡能传输数据；
- 让所有外设正常工作。

总之，**硬件的所有动作都要通过操作系统来完成**。

### 系统调用

操作系统会向开发者提供一组统一的编程接口（函数），称为**系统调用（System Call）**。程序员只要按照这组接口编程，就能方便地使用底层功能，而不用关心硬件细节。应用程序和操作系统之间是分层的：

```text
┌─────────────────────────┐
│       应用程序            │   例如浏览器、Python 脚本
├─────────────────────────┤
│   系统调用 / API 接口     │   操作系统提供给程序员的函数
├─────────────────────────┤
│         操作系统内核       │   管理 CPU、内存、磁盘、网卡
├─────────────────────────┤
│           硬件           │
└─────────────────────────┘
```

由此可以理解几件事：

- 操作系统内核和底层硬件紧密相关，所以**同一套操作系统不能随便跑在不同架构的硬件上**——比如 Windows 桌面版不能直接装进手机。
- 操作系统只负责管理硬件资源、让机器处于"可工作"状态；想玩游戏、看视频、上网，还得在其上安装专门的应用软件。
- 应用程序是针对特定操作系统的接口开发的，所以不同系统（Windows、macOS、Linux、iOS）上的软件一般不能通用。
