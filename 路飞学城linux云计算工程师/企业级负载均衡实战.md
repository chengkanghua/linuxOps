# 初识Nginx

## 常见Web服务器介绍

Web服务器是被动响应式的网络服务程序，当用户通过浏览器访问网站时，接收请求并返回网页内容，实现信息浏览和交互。

Unix/Linux平台上的常用Web服务器：
- **Apache**：开源免费，功能强大，稳定性好，传统企业网站主导
- **Nginx**：高性能，轻量级，现代Web标准，反向代理/负载均衡
- **Lighttpd**：高安全性，内存占用小，适合高并发场景
- **Tomcat**：Java应用服务器，支持Java Web应用开发
- **IBM WebSphere**：企业级Java应用服务器，功能丰富
- **Microsoft IIS**：Windows平台默认Web服务器，图形化管理

其中最广泛使用的是Nginx，在Windows平台上则常用IIS。

### Apache

Apache是世界主流的Web服务器，被众多著名网站使用。它的优势在于：
- 完全开源免费，拥有庞大的开发团队
- 支持跨平台运行（Unix/Linux/Windows）
- 模块化设计，功能可灵活扩展
- 稳定性极佳，经过多年生产环境验证

不足之处：属于重量级产品，内存消耗较高，性能和并发处理能力不如轻量级服务器，配置相对复杂。

### Lighttpd

Lighttpd是一款高安全性、快速且灵活的Web服务器，专为高性能环境设计。它相比其他服务器内存占用小，能有效管理CPU负载，支持FastCGI、SCGI、URL重写等重要功能，是Nginx的重要对手之一。

### Tomcat服务器

Tomcat是开源的Java Web应用服务器，负责运行基于Java的Web程序，支持Servlet和JSP规范。但对于高并发处理性能较弱，使用它需要对Java应用部署有足够了解。

### IBM WebSphere Application Server

WebSphere是企业级Java应用服务器，功能强大，用于开发、部署和管理Java相关的企业级Web应用，基于Java应用环境，支持复杂的企业级应用需求。

### Microsoft IIS

微软的IIS是Windows平台上常用的Web服务器，提供图形化管理界面，用于配置和管理网络服务，包含Web服务器、FTP服务器、SMTP服务器等多种功能。

缺点：只能运行在Windows系统，需要购买商业授权。

# Nginx

Nginx是俄罗斯开发者Igor Sysoev开发的高性能HTTP和反向代理服务器，以高性能、低资源消耗著称。

## 为何选择Nginx

在互联网快速普及、全球化和物联网发展的今天，Web服务器市场前三是Apache、IIS和Nginx，其中Nginx的市场份额一直在快速增长。

## Nginx资源消耗低/性能强

官方测试显示，Nginx可以支持5万并发连接，实际生产环境中通常能支撑2~4万并发连接数。

Apache使用传统的select网络IO模型，以多进程方式运行，需要频繁创建进程，系统资源消耗比Nginx高得多，且一个进程同一时间只能处理一个请求。

以LNMP架构为例，在3万并发连接下，10个Nginx进程总内存消耗仅约150MB；64个php-cgi进程总消耗约1.28GB，整个后台进程总使用不到2GB内存，资源占用极低。

在3万并发连接压力测试中，Nginx+PHP组合每秒可以处理约700个请求，日处理能力可达600万次以上，服务器负载仍然很低。

## Nginx成本低

Nginx的强大功能之一是反向代理和负载均衡，作为软件负载均衡，相比昂贵的硬件负载均衡设备（如F5、NetScaler），Nginx是开源软件，遵循BSD协议，可以免费使用甚至二次开发用于商业用途，成本优势非常明显。

## Nginx优势

- **配置简单易懂**：配置文件结构清晰，容易阅读和修改
- **灵活的重写功能**：支持Rewrite规则，可以根据域名、URL等条件将请求转发到不同的后端服务器
- **高可用性**：稳定性强，宕机概率极低
- **资源节省**：支持GZIP压缩静态资源，减少传输体积，节省带宽
- **热部署**：支持7*24小时不间断运行，可在不重启服务的情况下更新软件

## Nginx的网络模型

理解Nginx高性能的关键是它使用的网络IO模型，就像餐厅点餐的不同方式：

### 内核空间与用户空间

操作系统为了保护核心功能，将内存分为两个部分：
- **内核空间**：操作系统内核运行的区域，直接控制硬件
- **用户空间**：普通应用程序运行的区域，不能直接操作硬件和内核

### 进程阻塞

当进程等待某个操作完成（比如等待网络数据到达）时，会自动进入阻塞状态，不再占用CPU资源，直到事件完成后才会恢复运行。就像点餐时你坐在餐厅等待，这段时间没法做其他事。

### 文件描述符

系统为每个进程维护一个表格，记录进程打开的所有文件和网络连接，每个连接对应一个文件描述符（索引值）。

### Linux常见IO模型

网络IO操作分为两个阶段：
1. **等待数据准备**：等待网络数据到达服务器
2. **数据拷贝**：把数据从内核缓冲区复制到应用程序内存

不同的IO模型在这两个阶段的处理方式不同，这直接影响性能。Nginx之所以高性能，就是因为它使用了高效的网络IO模型，避免了传统模型中不必要的性能浪费。

常见的IO模型有：阻塞IO、同步非阻塞、IO多路复用、异步IO，Nginx使用的是高效的epoll（IO多路复用）模型。

### 同步阻塞IO（block IO）

这就像在麦当劳点餐，点过之后只能坐在餐厅等待，直到用餐结束才离开，这段时间没法做其他事。这种模式简单，适合开发，但性能较弱，当连接数较多时效率较低。

### 同步非阻塞

这种模式下，进程不会一直等待，而是每隔一段时间主动询问内核数据是否准备好，这样CPU可以去做其他事情，但缺点是需要频繁轮询，也会有性能损耗。

### IO多路复用

这种模式就像餐厅装了电子进度屏，你不用来回跑着问，直接看屏幕就知道哪份餐做好了。可以同时监听多个网络连接，当某个连接的数据准备好时，才通知应用程序进行处理，避免了频繁轮询的开销。Linux系统中的select、poll、epoll就是实现了这种机制，其中epoll是目前效率最高的方式，Nginx使用的就是epoll模型。

### 异步IO模型

这种模式最轻松，你不用在餐厅等，也不用来回询问，直接回家休息点外卖，饭做好了外卖员直接送到家。应用程序发起IO操作后，立刻返回继续做其他事情，内核负责处理数据的等待和拷贝，数据准备完成后，内核会通知应用程序，进程全程不会被阻塞，性能最高。

### 网络IO模型总结

- **阻塞与非阻塞**：阻塞IO会等待整个操作完成才返回，非阻塞IO如果没有数据会立即返回错误
- **同步与异步**：同步IO在操作过程中会阻塞进程，异步IO全程不会阻塞进程

Nginx使用的epoll正是高效实现了IO多路复用的机制，这是它能支撑高并发的核心原因。

## Nginx配置详解

Nginx的配置文件就像一本"餐厅运营手册"，结构清晰，分为多个核心部分：

### 配置文件结构

Nginx配置由**指令**和**指令块**组成，有几个重要规则：
- 每条指令以分号`;`结尾，就像句子要加句号
- 相关指令用大括号`{}`组成"小组"，类似不同部门分工
- 以`#`开头的是注释，不会被执行，适合添加说明
- 支持`$变量`和`include`包含其他配置文件，方便模块化管理

Nginx配置分为三个核心部分：
1. **全局指令**：影响Nginx整体运行，比如设置进程数、日志存放路径
2. **events块**：处理网络连接的配置，比如最大连接数相关
3. **http块**：配置HTTP核心功能，包含多个server虚拟主机子块，对应不同网站

### 基础配置示例
```nginx
# 全局配置
user nobody;              # 运行Nginx的系统用户，建议用非root用户
worker_processes 1;      # Nginx进程数，建议等于CPU核心数，充分利用多核性能
error_log logs/error.log notice;  # 全局错误日志及级别
pid logs/nginx.pid;      # 记录Nginx主进程ID的文件，方便管理

# events块：处理网络连接
events {
    use epoll;            # 使用epoll事件模型，Linux推荐，效率最高
    worker_connections 1024;  # 单个进程允许的最大连接数
    keepalive_timeout 60;     # 长连接超时时间（秒）
}

# http块：核心HTTP服务配置
http {
    include mime.types;       # 文件扩展名与文件类型映射表
    default_type application/octet-stream;  # 默认文件类型
    
    # 日志格式定义
    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                    '$status $body_bytes_sent "$http_referer"';
    access_log logs/access.log main;  # 访问日志路径
    
    sendfile on;        # 开启高效文件传输模式，减少数据拷贝
    tcp_nopush on;      # 减少网络包数量，提升性能
    keepalive_timeout 65;  # 长连接超时时间，减少频繁建立连接的开销
    
    # server块：虚拟主机，对应一个网站
    server {
        listen 80;               # 监听80端口（HTTP默认端口）
        server_name localhost;   # 服务器名称，对应域名
        
        # 处理根路径请求
        location / {
            root html;          # 网站根目录
            index index.html index.htm;  # 默认首页文件
        }
        
        # 错误页面配置
        error_page 404 /404.html;
        error_page 500 502 503 504 /50x.html;
        location = /50x.html {
            root html;
        }
    }
}
```

### 关键配置说明
- `worker_processes`：进程数，建议设置为CPU核心数，充分利用多核性能
- `worker_connections`：单个进程最大连接数，总连接数=进程数×连接数
- `use epoll`：事件模型，Linux系统使用epoll能大幅提升并发处理能力
- `sendfile on`：零拷贝技术，减少数据拷贝次数，提升文件传输效率
- `keepalive_timeout`：长连接时间，减少频繁建立连接的开销

### 配置文件注释

Nginx配置文件中可以用`#`添加注释，帮助理解每个配置项的作用。大型网站会把配置拆分成多个文件，通过`include`语句包含，方便模块化管理。

## Nginx安装配置

Nginx有两种安装方式：**yum自动安装**（简单快捷，适合快速上手）和**源码编译安装**（灵活度高，可以自定义扩展功能，适合定制化场景）。

### 环境准备
安装Nginx需要一些依赖库来支持不同功能（比如压缩、URL重写、HTTPS等），可以执行以下命令一键安装：
```bash
yum install -y gcc gcc-c++ autoconf automake make zlib zlib-devel openssl openssl-devel pcre pcre-devel wget httpd-tools vim
```

### 源码编译安装步骤
```bash
# 1. 下载源代码
wget nginx.org/download/nginx-1.14.0.tar.gz

# 2. 解压并进入目录
tar -zxf nginx-1.14.0.tar.gz
cd nginx-1.14.0

# 3. 配置编译选项（按需选择模块）
./configure --prefix=/home/Learn_Nginx/nginx/ \
    --with-http_ssl_module \
    --with-http_flv_module \
    --with-http_gzip_static_module \
    --with-http_stub_status_module \
    --with-threads \
    --with-file-aio

# 4. 编译并安装
make && make install

# 5. 配置环境变量，方便直接使用nginx命令
echo 'export PATH=/home/Learn_Nginx/nginx/sbin:$PATH' >> /etc/profile.d/nginx.sh
source /etc/profile.d/nginx.sh

# 6. 验证安装
nginx -v          # 查看版本
nginx -V          # 查看编译模块信息
```

## Nginx命令行管理

Nginx提供了丰富的命令行操作，方便日常管理：

### 常用操作
- 启动服务：`nginx`
- 立即停止服务：`nginx -s stop`（强制关闭，不处理现有请求）
- 优雅停止服务：`nginx -s quit`（处理完现有请求后再停止）
- 重载配置：`nginx -s reload`（修改配置后不中断服务，平滑生效）
- 测试配置语法：`nginx -t`（检查配置文件是否有语法错误）

### 完整命令帮助
```bash
# 查看所有可用命令和参数
nginx -h
```

## 配置文件重载（不中断服务）

修改Nginx配置后，不需要停止服务，直接重载即可让新配置生效，这是生产环境常用的操作方式：
```bash
# 1. 先修改配置文件，比如调整进程数、添加新站点
vim /usr/local/nginx/conf/nginx.conf

# 2. 测试配置语法是否正确（必须做！避免配置错误导致服务异常）
nginx -t

# 如果显示：nginx: configuration file /usr/local/nginx/conf/nginx.conf test is successful
# 说明配置没有问题，再执行重载命令：
nginx -s reload

# 3. 验证是否生效，查看worker进程
ps -ef | grep nginx
```

## Nginx进程信号管理

Nginx采用master-worker模式，master进程负责管理worker，通过发送信号实现各种功能：

| `nginx -s` | 信号 | 作用 |
|------------|------|------|
| `stop` | TERM | 强制关闭整个服务 |
| `quit` | QUIT | 优雅关闭，处理完现有请求后停止 |
| `reload` | HUP | 重载配置，启动新worker，优雅关闭旧worker |
| `reopen` | USR1 | 重新打开日志文件，用于日志切割 |
| - | USR2 | 平滑升级，二进制文件替换 |
| - | WINCH | 优雅关闭旧worker，用于版本升级 |

## 热部署（版本升级）

热部署可在不中断服务的情况下升级Nginx版本，流程如下：
1. 备份旧二进制文件
2. 编译安装新版本
3. 发送信号实现版本切换：
   - USR2：启动新master进程
   - WINCH：优雅关闭旧worker
   - QUIT：关闭旧master进程

注意：旧版本必须用绝对路径启动，否则信号可能失效。

## Nginx日志切割

线上服务的日志会不断增长，需要定期切割（拆分）日志文件，避免单个日志文件过大，方便管理和分析。

### 手动切割日志
```bash
# 1. 进入日志目录
cd /usr/local/nginx/logs

# 2. 查看当前日志，确认文件大小
ll

# 3. 重命名当前日志文件（添加时间戳备份）
# 使用mv命令而不是cp，因为mv只是修改文件名，速度快且不丢失inode
mv access.log access.log_$(date +"%Y-%m-%d_%H:%M")

# 4. 通知Nginx重新打开日志，生成新的日志文件
# 相当于触发日志切割，无需停止服务
nginx -s reopen

# 也可以使用kill信号方式：kill -USR1 `cat nginx.pid`
```

### 自动切割（生产环境常用）

手动切割太麻烦，生产环境一般用`crontab`定时执行脚本，每天自动切割日志。

```bash
# 1. 创建切割脚本cut_nginx_log.sh
vim /usr/local/nginx/sbin/cut_nginx_log.sh

# 脚本内容：
#!/bin/bash
# 日志存放路径
logs_path="/usr/local/nginx/logs/"

# 创建按日期分类的目录，方便管理
mkdir -p ${logs_path}$(date -d "yesterday" +"%Y")/$(date -d "yesterday" +"%m")

# 把昨天的日志移动到对应日期目录，并改名
mv ${logs_path}access.log ${logs_path}$(date -d "yesterday" +"%Y")/$(date -d "yesterday" +"%m")/access_$(date -d "yesterday" +"%Y-%m-%d").log

# 通知Nginx生成新日志
kill -USR1 `cat ${logs_path}nginx.pid`

# 2. 给脚本添加执行权限
chmod +x /usr/local/nginx/sbin/cut_nginx_log.sh

# 3. 添加到定时任务，每天0点自动执行
crontab -e

# 添加一行：
0 0 * * * /usr/local/nginx/sbin/cut_nginx_log.sh
```

## Nginx虚拟主机

虚拟主机就是在一台服务器上，通过Nginx同时运行多个独立的网站（站点），每个网站有独立的域名，用户看起来像单独的服务器。

### 为什么用虚拟主机？
- 节省资源：一台服务器就能跑多个网站，不需要每个网站单独用一台服务器
- 降低成本：减少硬件和运维成本
- 灵活管理：网站之间相互隔离，配置互不影响

想象一下：一个服务器就像一栋大楼，每个虚拟主机就是里面的不同房间，各有各的用途，共用大楼的水电等基础设施。

### 虚拟主机配置示例

在nginx.conf的http块里，通过server指令块配置虚拟主机：

```nginx
http {
    # ... 其他配置 ...
    
    # 第一个虚拟主机：监听80端口，对应域名localhost
    server {
        listen 80;                # 监听80端口（HTTP默认端口）
        server_name localhost;    # 匹配的域名
        charset utf-8;           # 默认编码，支持中文
        
        # 访问日志路径，使用main格式
        access_log logs/host.access.log main;
        
        # 根路径配置
        location / {
            root html;            # 网站根目录
            index index.html index.htm;  # 默认首页文件
        }
    }
}
```

### 搭建静态资源网站（示例）

假设我们要在服务器上创建一个静态网站，步骤如下：

#### 1. 准备网站文件
先把网站的所有文件放在一个目录里，比如`/website`：
```bash
# 创建网站目录
mkdir -p /website

# 上传网站文件，至少要有首页index.html
# 比如：
cd /website
ls
# 输出：index.html  pic （还有其他图片、CSS等资源）
```

#### 2. 修改Nginx配置
修改nginx.conf，找到第一个server{}指令块，改成自己的网站配置：
```nginx
server {
    listen       80;                # 监听80端口，HTTP默认端口
    server_name  localhost;         # 匹配的域名，也可以写实际域名
    charset utf-8;                  # 默认编码，支持中文
    access_log  logs/host.access.log  main;  # 访问日志
    
    # 处理根路径请求
    location / {
        root   /website/;           # 指定网站根目录，对应我们创建的/website
        index  index.html index.htm;  # 默认首页文件名
    }
}
```

#### 3. 重载配置，让修改生效
```bash
nginx -s reload
```

#### 4. 访问网站
现在就可以通过浏览器访问了：
- 访问首页：`http://你的服务器IP`（自动解析到index.html）
- 访问具体页面：`http://你的服务器IP/index.html`
- 访问图片：`http://你的服务器IP/pic/2.jpg`（如果有图片的话）

只要把你的域名解析到服务器IP，用户就能通过域名访问这个网站了。

### 基于IP的虚拟主机

除了用域名区分，还可以通过不同的IP地址来区分多个网站。就像一台服务器有两个不同的地址，每个地址对应不同的网站。

#### 步骤1：给服务器添加多个IP地址
一块网卡可以绑定多个IP，这样就能用IP来区分网站：
```bash
# 给网卡ens33添加第二个IP（别名）
ifconfig ens33:1 192.168.178.200 broadcast 192.168.178.255 netmask 255.255.255.0 up

# 查看IP是否添加成功
ifconfig | grep 192
# 应该看到两个IP：192.168.178.181 和 192.168.178.200

# 测试两个IP都能正常访问
curl 192.168.178.181
curl 192.168.178.200
```

#### 步骤2：配置Nginx支持基于IP的虚拟主机
修改nginx.conf，创建两个server块，分别对应两个IP：
```nginx
# 第一个虚拟主机，对应IP 192.168.178.181
server {
    listen 192.168.178.181:80;  # 监听这个IP的80端口
    server_name 192.168.178.181;
    charset utf-8;
    access_log logs/host.access.log;
    
    location / {
        root /website/s1;  # 第一个网站的文件目录
        index index.html index.htm;
    }
}

# 第二个虚拟主机，对应IP 192.168.178.200
server {
    listen 192.168.178.200:80;
    server_name 192.168.178.200;
    charset utf-8;
    access_log logs/host.access.log;
    
    location / {
        root /website/s2;  # 第二个网站的文件目录
        index index.html index.htm;
    }
}
```

#### 步骤3：准备网站文件
```bash
# 创建网站目录，并写入不同内容
echo "我是来自192.168.178.181的网站" > /website/s1/index.html
echo "我是来自192.168.178.200的网站" > /website/s2/index.html

# 重载Nginx配置，让修改生效
nginx -s reload
```

#### 测试效果
现在访问两个IP，应该会看到不同的内容：
- 访问 `http://192.168.178.181` → 显示来自181的网站内容
- 访问 `http://192.168.178.200` → 显示来自200的网站内容

这样就实现了基于IP的虚拟主机，用同一个服务器的不同IP来区分不同网站。

## Nginx访客日志功能

日志对于程序员很重要，可用于问题排错，记录程序运行状态，一个好的日志能够给与精确的问题定位。

Nginx日志功能需要在nginx.conf中打开相关指令`log_format`，设置日志格式，以及设置日志的存储位置`access_log`，指定日志的格式，路径，缓存大小。

```plain
nginx.conf中有关访客日志定义如下
 #a
log_format  main  '$remote_addr - $remote_user [$time_local] "$request" '
                      '$status $body_bytes_sent "$http_referer" '
                    '"$http_user_agent" "$http_x_forwarded_for"';
 access_log  logs/access.log  main;
参数解释 
$remote_addr ：记录访问网站的客户端地址
$remote_user ：记录远程客户端用户名称
$time_local ：记录访问时间与时区
$request ：记录用户的 http 请求起始行信息
$status ：记录 http 状态码，即请求返回的状态，例如 200 、404 、502 等
$body_bytes_sent ：记录服务器发送给客户端的响应 body 字节数
$http_referer ：记录此次请求是从哪个链接访问过来的，可以根据 referer 进行防盗链设置
$http_user_agent ：记录客户端访问信息，如浏览器、手机客户端等
$http_x_forwarded_for ：当前端有代理服务器时，设置 Web 节点记录客户端地址的配置，此参数生效的前提是代理服务器上也进行了相关的 x_forwarded_for 设置
```

查看日志格式
```bash
tail -2 logs/access.log
# 输出示例：
# 192.168.178.1 - - [11/Feb/2020:19:24:37 +0800] "GET / HTTP/1.1" 304 0 "-" "Mozilla/5.0 (Macintosh; Intel Mac OS X 10_15_3) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/79.0.3945.130 Safari/537.36"
# 127.0.0.1 - - [12/Feb/2020:10:26:26 +0800] "GET / HTTP/1.1" 200 65 "-" "curl/7.29.0"
```

### Nginx的浏览器缓存

配置浏览器缓存可以加速静态资源的访问，浏览器对用户访问的资源进行存储，下次访问，不用再去向服务器寻求资料，直接本地显示，加速访问体验，节省网络资源，提高效率。

Nginx通过expires指令配置缓存，可以控制HTTP响应中的Expires和Cache-Control的头部信息，用来控制页面缓存。

例如HTML页面经常引用JavaScript以及图片等文件，这些文件很少被修改，可以设置浏览器对该类资源在本地缓存定期的时间。

添加缓存配置之后响应信息：

```nginx
location ~* \.(gif|jpg|jpeg|png|bmp|swf)$ {
    root /website/s1/;
    expires 30d;
}

location ~* \.(js|css)?$ {
    root /website/s1/;
    expires 1h;
}
```

### Nginx配置文件拆分（模块化管理）

当Nginx配置越来越复杂，有多个虚拟主机和功能模块时，可以用`include`指令把配置拆分成多个文件，就像把一本书分成几个章节，方便管理和修改。

#### 为什么拆分配置？
- **分工协作**：多个开发人员可以同时修改不同配置文件
- **清晰易懂**：每个虚拟主机的配置在单独文件里，不会和其他配置混在一起
- **便于维护**：修改某个网站配置不会影响其他网站

#### 配置拆分步骤
```bash
# 1. 创建专门放拆分配置的目录
mkdir -p /opt/nginx/conf/extra

# 2. 拆分虚拟主机配置
# 把第一个虚拟主机配置导出到单独文件
sed -n '29,87p' nginx.conf > extra/bbs.conf
sed -i '29,87d' nginx.conf  # 删除主配置里的这段

# 把第二个虚拟主机配置导出到单独文件
sed -n '29,41p' nginx.conf > extra/blog.conf
sed -i '29,41d' nginx.conf  # 删除主配置里的这段

# 3. 主配置文件中添加include，导入所有拆分的配置
http {
    include mime.types;
    default_type application/octet-stream;
    
    # 其他全局配置...
    
    # 导入extra目录下所有.conf文件
    include extra/*.conf;
}
```

现在每个虚拟主机的配置在单独文件里，修改起来更方便，也不会出错。

## Nginx错误日志配置

Nginx会把运行时发生的错误记录到日志文件里，就像电脑的"错误记事本"，方便后续排查问题。

### 日志级别选择
日志有不同级别，级别越高，记录的信息越少，适合生产环境用：

| 级别 | 说明 | 生产环境建议 |
|------|------|--------------|
| debug | 最详细的调试信息 | ❌ 不建议用（会产生大量日志） |
| info | 一般运行信息 | ❌ 不建议用（IO开销大） |
| notice | 正常但重要的事件 | ❌ 不建议 |
| warn | 警告信息 | ✅ 建议用 |
| error | 错误信息 | ✅ 推荐使用 |
| crit | 严重错误 | ✅ 推荐使用 |
| alert | 需要紧急处理的错误 | ✅ 推荐使用 |
| emerg | 系统不可用 | ✅ 推荐使用 |

**生产环境推荐用`error`或`warn`级别，既够用来排障，又不会产生太多日志占用磁盘。**

### 配置错误日志
在nginx.conf中添加错误日志配置，既可以全局配置，也可以在每个虚拟主机单独配置：
```nginx
# 全局配置（在http块中）
http {
    error_log logs/error.log error;  # 全局错误日志，级别error
    
    # 虚拟主机单独配置（在server块中）
    server {
        listen 80;
        server_name www.chaogelinux.com;
        
        # 这个网站的错误日志单独存
        error_log logs/www.chaogelinux.error.log;
        
        location / {
            root /website/s1;
            index.html index.htm;
        }
    }
}
```

修改后重载生效：
```bash
nginx -s reload
```

查看日志文件：
```bash
ls /opt/nginx/logs/
# 会看到 error.log 和 www.chaogelinux.error.log 等文件
```

## Nginx location路径匹配规则

Nginx通过location指令，根据用户请求的URL路径灵活匹配，执行不同的操作。

### Location语法
```nginx
location [匹配符] 路径 {
    # 匹配成功后的配置
}
```

### 常用匹配符（按优先级从高到低）
| 匹配符 | 说明 | 优先级 |
|--------|------|--------|
| `=` | 精确匹配整个路径 | 1（最高） |
| `^~` | 匹配路径开头，不解析正则 | 2 |
| `~*` | 正则匹配（不区分大小写） | 3 |
| 普通路径 | 匹配路径前缀 | 4 |
| `/` | 通用匹配（默认规则） | 5（最低） |

### 匹配示例
假设请求路径：
- `/` → 匹配配置A
- `/index.html` → 匹配配置B
- `/blog/blog.html` → 匹配配置C
- `/img/1.jpg` → 匹配配置D
- `/blog/1.jpg` → 匹配配置E

### 配置示例
```nginx
server {
    listen 83;
    server_name _;
    
    # 通用匹配（所有请求默认规则）
    location / {
        return 401;
    }
    
    # 精确匹配根路径 /
    location = / {
        return 402;
    }
    
    # 匹配 /blog/ 开头的路径
    location /blog/ {
        return 403;
    }
    
    # 匹配 /img/ 开头的路径（不解析正则）
    location ^~ /img/ {
        return 404;
    }
    
    # 匹配 .gif/.jpg 等图片文件（正则匹配，不区分大小写）
    location ~* \.(gif|jpg|jpeg)$ {
        return 500;
    }
}
```

### 测试匹配结果
```bash
# 精确匹配根路径，返回402
curl -s -I -w "%{http_code}\n" http://127.0.0.1:83
curl -s -I -w "%{http_code}\n" http://127.0.0.1:83/

# 其他路径，返回401
curl -s -I -w "%{http_code}\n" http://127.0.0.1:83/index.html

# /blog/ 开头，返回403
curl -s -I -w "%{http_code}\n" http://127.0.0.1:83/blog/index.html

# /img/ 开头，返回404
curl -s -I -w "%{http_code}\n" http://127.0.0.1:83/img/2.gif

# /blog/ 下的图片，正则匹配，返回500
curl -s -I -w "%{http_code}\n" http://127.0.0.1:83/blog/1.gif
```

## Nginx URL重写（rewrite）

URL重写就像"网页翻译"，可以把用户访问的URL自动转换成另一个地址，常用于：
- 把带问号的动态URL（比如PHP地址）伪装成.html静态地址，方便搜索引擎收录
- 网站搬家或换域名时，自动把旧地址跳转到新地址，避免用户找不到
- 封禁恶意爬虫，让它们跳转到无效页面，减少服务器压力

#### 基本语法
```nginx
location / {
    # 语法：rewrite 正则表达式 替换地址 [标志];
    rewrite ^/topic-(\d+)\.html$ /topic.php?id=$1 last;
}
```

#### 常用标志
- `last`：停止当前rewrite，重新发起新请求
- `break`：停止处理，直接返回当前内容
- `redirect`：临时重定向（返回302）
- `permanent`：永久重定向（返回301，搜索引擎会更新缓存）

### 基本语法
```nginx
rewrite 正则表达式 目标URL [flag];
```

示例：将所有请求跳转到百度
```nginx
rewrite ^/(.*) http://www.baidu.com/$1 permanent;
```

### 常用flag标记（决定跳转行为）
| 标记 | 作用 | 浏览器地址栏 |
|------|------|--------------|
| last | 完成匹配后继续向下匹配新location | 地址不变 |
| break | 完成匹配后立即停止处理 | 地址不变 |
| redirect | 返回302临时重定向 | 显示跳转后的URL |
| permanent | 返回301永久重定向 | 显示跳转后的URL |

**last/break用于内部URL重写，地址栏不变化；redirect/permanent用于外部跳转，地址栏变化。**

### 301永久跳转示例
```nginx
server {
    listen 90;
    server_name _;
    # 将所有请求跳转到百度
    rewrite ^/(.*) http://www.baidu.com/$1 permanent;
}
```


## Nginx的核心模块

### Nginx访问控制模块（IP限制）
通过IP地址限制访问，只允许特定IP或IP段访问网站，防止恶意IP攻击。

示例：只允许公司内网访问后台
```nginx
location /admin/ {
    allow 192.168.1.0/24;  # 允许192.168.1.0网段访问
    allow 127.0.0.1;       # 允许本地访问
    deny all;              # 拒绝其他所有IP
}
```

### Nginx的连接限制模块（连接数限制）
限制单个IP的并发连接数，防止某个IP占用过多资源，影响其他用户。

示例：限制单个IP最多10个连接
```nginx
http {
    limit_conn_zone $binary_remote_addr $limit 10m;  # 定义连接数限制区域
    
    server {
        location / {
            limit_conn conn 10;  # 限制单个IP最多10个连接
            root html;
            index index.html;
        }
    }
}
```

### Nginx的压缩模块（gzip）
对静态资源进行gzip压缩，减少传输体积，提升加载速度，节省带宽。

示例配置：
```nginx
http {
    gzip on;  # 开启gzip压缩
    gzip_min_length 1k;  # 只压缩超过1k的文件
    gzip_buffers 4 16k;  # 压缩缓冲区
    gzip_http_version 1.1;  # 压缩版本
    gzip_comp_level 2;  # 压缩等级，1-9，适中值2
    gzip_types text/plain application/x-javascript text/css application/xml;  # 要压缩的文件类型
    gzip_vary on;  # 让缓存服务器也知道文件被压缩了
}
```

### Nginx的防盗链模块（invalid referer）
防止其他网站直接引用自己的图片、文件，占用带宽。

示例配置：
```nginx
location ~* \.(gif|jpg|jpeg|png|bmp|swf)$ {
    valid_referers none blocked *.chaoge.com;
    if ($invalid_referer) {
        return 403;  # 禁止直接盗链，返回403错误
    }
}
```

### Nginx的状态模块（stub_status）
查看Nginx的运行状态，比如并发连接、处理的请求数等。

示例配置：
```nginx
location /status {
    stub_status on;
    access_log off;
    allow 127.0.0.1;  # 只允许本地访问状态页
    deny all;
}
```

访问 `http://你的IP/status` 就能看到Nginx的实时状态，包括当前活跃连接数、总请求数等。

## LNMP环境搭建

### LNMP简介
LNMP是Linux + Nginx + MySQL + PHP的组合，是搭建动态网站的常用架构，WordPress、Discuz等程序都常用这个架构。

### MySQL数据库安装配置

MySQL是网站的"数据仓库"，专门用来存储网站的用户、文章等数据，读写性能特别好，是Web应用的标准配置。MySQL使用二维表来存储数据，将不同的数据分类存储在不同的表中，这种设计大幅提升了读写速度。

### PHP安装与配置
PHP是处理动态请求的脚本语言，负责处理网站的逻辑，和Nginx配合实现动态网站。

### FastCGI与PHP-FPM

FastCGI是动态脚本语言（如PHP）和Web服务器之间的通信协议，它解决了传统CGI性能低下的问题。PHP-FPM是PHP的FastCGI进程管理器，负责管理PHP进程，让Nginx能高效地处理动态请求。

传统的CGI方式：
- 每次处理动态请求都要启动新进程
- 请求结束后进程就销毁
- 高并发时需要大量进程，资源消耗大
- 处理效率低，不适合高流量场景

FastCGI和PHP-FPM的改进：
- 进程常驻内存，避免频繁创建/销毁的开销
- 一个进程可以处理多个请求
- 支持进程池，可配置进程数量
- 性能大幅提升，适合生产环境使用

### Nginx配置支持PHP
需要在Nginx中配置location块，处理以.php结尾的请求，转发给PHP-FPM处理，实现动静分离，提升服务器整体性能。

示例配置：
```nginx
location ~ \.php$ {
    fastcgi_pass 127.0.0.1:9000;  # 转发给PHP-FPM处理动态请求
    fastcgi_index index.php;
    include fastcgi.conf;
}
```

### 测试LNMP环境
创建一个PHP测试文件，测试Nginx是否能正确处理PHP请求：
```bash

echo "<?php phpinfo(); ?>" > /website/blog/test_info.php
```

访问 `http://你的IP/test_info.php`，如果能看到PHP信息页面，说明LNMP环境已经成功。


访问这个PHP文件，如果能看到连接成功的提示，说明PHP和MySQL都配置正确。
