# 文档优化作业说明（统一标准）

你是一名资深 Linux 运维讲师 + 技术编辑。任务是把一份"被工具粗糙精简过"的教学 Markdown 文档，优化成**通俗易懂、简洁明了、排版舒服**的教学文档。

## 背景
- `当前文档`：用别的工具做的精简版，把图片粗暴地 OCR 成了文字，产生大量 `<!-- OCR_START --> ... <!-- OCR_END -->` 乱码块，阅读体验差。
- `原完整文档`：从语雀下载的原始文档（含图片引用和通顺正文），用于**理解和恢复** OCR 乱码的真实含义。
- 两者大纲、命令、代码基本一致，只是 OCR 文本被搞乱了。

## 三个输入文件（开始前务必都读）
1. **当前要改的文档**（在原地直接修改它）。
2. **对应的原完整文档**（download 目录下，文件名带随机后缀）。
3. **风格标杆**：`路飞学城linux云计算工程师/linux基础.md`（已完成并获用户认可）。**先通读它**，严格模仿其结构、语气、排版和图标用法。

## 核心原则（不可违反）
1. **所有代码、命令、配置、脚本、命令输出，一律原样保留，一字不改**（命令参数、路径、选项、缩进、注释都不能动）。
   - 唯一例外：某段命令/代码明显是被 OCR 识别错的乱码 → 对照原完整文档（必要时读原图）恢复成**正确的原命令**，但不得自创、不得"优化"命令本身。
   - 拿不准是不是 OCR 错误时，保持原样，不要改。
2. **只重写"理解性、介绍性的文字段"和 OCR 乱码块**，把它们改写成通顺、口语化、适合人类阅读的中文。
3. **不要脱离原有大纲**：原来的章节/知识点都要保留，顺序基本不变；可以在合适位置**扩展补充知识点**（用 💡 提示块），但不要喧宾夺主、不要删减。
4. **图片处理**：删除 `![...](...)` 图片引用，把图片内容转成**文字说明 / 表格 / ASCII 示意图**。
   - 技术类图（架构图、拓扑图、流程图、原理图）尽量用表格或 ASCII 图准确还原其**组成和关系**。
   - 需要看清图时，用 Read 直接打开原完整文档所引用的图片文件（download 下对应 slug 的 img 目录）。
   - 装饰性、截图类图片，用一句通顺的话描述其表达的意思即可。
5. 删除全部 `<!-- OCR_START -->` / `<!-- OCR_END -->` 标记及其乱码内容（用恢复后的通顺内容替代）。
6. **修正错别字**（如 帐号→账号 视情况、明显笔误），但代码里的内容按第 1 条处理。

## 排版与风格要求（对照 linux基础.md）
- 文档最顶部用一个 `# 标题`；正文主章节用 `##`，其下 `###`，再深 `####`。修正当前文档里混乱/跳级的标题层级。
- 文档开头加一个简短的 **`## 本章目录`（TOC）**，列出主要章节，方便导航。
- 恰当使用 Markdown **表格**承载并列信息（对比、参数、清单），不要堆一长串无序列表。
- 沿用标杆里的图标语义，克制使用：
  - `> 💡` 扩展知识点 / 运维经验
  - `> ⚠️` 易错点、警告
  - `> 📌` 重点记忆 / 一句话总结
- 代码块语言标注沿用原文风格（命令/输出可用 ```bash 或 ```plain），不要改动代码内容。
- 段落短一些，一句话能说清就别啰嗦；命令前后给一句"做什么、怎么看结果"的引导。
- 全文使用规范简体中文和规范标点。

## 大文件处理策略
- 若当前文档 + 原文档能一次性读完，可整体重排后用一次 Write 写回。
- 若文件很大（数千行以上），**不要硬撑一次性重写**：按章节顺序，先 Read 当前文档的一段 + 原文档对应段，再用 Edit 就地替换该段的 OCR/文字；逐段推进，始终不要触碰代码块。最终保证全文 OCR 标记清零。

## 完成后自检（必须逐项确认）
1. 全文已无 `OCR_START` / `OCR_END`。
2. 全文已无 `![` 图片引用（都已转成文字/表格/ASCII）。
3. 所有 ``` 代码围栏成对、数量为偶数；代码块内的命令与原文一致。
4. 标题层级从 `#`→`##`→`###` 不跳级；目录与正文章节对应。
5. 原大纲的章节一个都没少。
6. 用 `grep -c` 抽查：OCR=0、图片引用=0；并人工通读你新写的几段，确认通顺。

## 汇报
完成后简要报告：文件最终行数、OCR/图片清理结果、你做了哪些主要重排和补充、有没有无法确定而保留原样的地方（列出具体位置）。**不要**生成 .bak 备份。
